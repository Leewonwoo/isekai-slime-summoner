# Cross Defense 기능 단위 MVP 계획서

## 1. 목적

이 문서는 날짜별 일정표가 아니라, 게임을 구성하는 기능을 **구현 단위와 테스트 단위**로 나누어 관리하기 위한 계획서다.

MVP의 기준은 콘텐츠를 일부만 넣은 축소판이 아니다.

> `StageTimeline`에 정의된 임의의 스테이지가 시작부터 종료까지 실행되고, 기획서의 유닛·몬스터·성장·이벤트 콘텐츠를 같은 런타임 시스템에 연결할 수 있는 상태

콘텐츠는 가능한 범위에서 기획서의 전체 목표를 유지한다. 기능 구현은 골격부터 만들고, 데이터와 에셋을 단계적으로 채운다.

## 2. 확정된 게임 규칙

- 4방향 레인과 고정 슬롯 시스템은 사용하지 않는다.
- 소환사는 화면 중앙에 고정되고 원거리 자동 공격을 한다.
- 필드 밖의 확장 스폰 영역에서 몬스터가 다양한 위치로 등장한다.
- 몬스터는 소환사를 향해 이동한다.
- 소환수는 필드에서 자유롭게 이동하며 적을 탐색하고 자동 공격한다.
- 소환창의 유닛 카드를 필드로 드래그해 배치할 수 있다.
- 소환 버튼을 누르면 유닛이 소환사 주변의 유효한 위치에 자동 배치된다.
- 같은 종류·같은 성급의 유닛 3개를 인게임에서 머지한다.
- 유닛을 다른 유닛 위로 드래그하면 머지 가능 여부를 판정한다.
- 소환사는 자동 공격 외에 필드 클릭 위치를 향해 공격할 수 있다.
- 습득한 스킬은 쿨다운마다 조건에 따라 자동 발동한다.
- 웨이브 수와 웨이브 구성은 `StageTimeline`이 결정한다. 웨이브 수를 코드에 하드코딩하지 않는다.
- 설정된 간격마다 기본 3개 특성 중 1개를 선택한다. 기본 간격은 5웨이브지만 스테이지 설정값으로 둔다.
- 황금 고블린과 행상인은 웨이브 또는 인터미션 이벤트로 설정할 수 있다.
- 기획서의 전체 소환수·몬스터 콘텐츠는 같은 데이터 기반 시스템에 연결한다.

## 3. 테스트 레벨

| 레벨 | 대상 | 목적 |
|---|---|---|
| L0 EditMode | 순수 규칙·계산·데이터 검증 | 빠른 회귀 테스트 |
| L1 PlayMode | 프리팹·월드·전투·UI 상호작용 | 실제 런타임 흐름 검증 |
| L2 Device | Android APK 실기기 | 터치, 성능, 해상도, 입력 검증 |
| L3 Full Run | 임의의 `StageTimeline` 전체 런 | 기능 연결과 회귀 검증 |

권장 테스트 폴더:

```text
Assets/Tests/EditMode/
Assets/Tests/PlayMode/
docs/tests/
```

## 4. 기능 단위 계획

### F-01. 런타임 상태와 StageTimeline 실행기

구현:

- `StageTimeline` 로드
- 타임라인의 웨이브 수를 HUD와 진행 로직에 바인딩
- `Prepare`, `InWave`, `Intermission`, `TraitChoice`, `Merchant`, `Victory`, `Defeat` 상태 정의
- 현재 웨이브와 다음 이벤트 관리
- 잘못된 타임라인 데이터 검증

테스트 단위:

- L0: 웨이브 수가 3, 7, 13 등 임의의 값으로 정상 계산되는가
- L0: 빈 웨이브·몬스터가 없는 웨이브·잘못된 참조가 검증되는가
- L1: 준비 → 전투 → 보상 → 다음 웨이브 전환이 되는가
- L3: 마지막 웨이브 이후 추가 웨이브를 실행하지 않는가

완료 기준: 코드에 특정 웨이브 수가 없고, 타임라인만 교체해 다른 스테이지를 실행할 수 있다.

### F-02. 카메라·필드·외곽 스폰 영역

구현:

- 세로 화면 기준의 월드 필드
- 중앙 소환사 앵커
- 카메라 뷰포트 바깥의 확장 스폰 사각형 또는 링
- 외곽 스폰 구역별 가중치와 랜덤 시드
- 스폰 위치가 화면 안에 즉시 보이지 않도록 보정

테스트 단위:

- L0: 동일 시드에서 동일한 스폰 위치 순서가 재현되는가
- L1: 몬스터가 화면 밖에서 생성되는가
- L1: 여러 스폰 구역에서 위치가 충분히 분산되는가
- L2: 화면 비율과 안전 영역이 달라도 스폰 영역이 깨지지 않는가

완료 기준: 고정 레인 없이 화면 바깥 여러 위치에서 몬스터가 등장한다.

### F-03. 몬스터 생명주기

구현:

- 스폰, 이동, 소환사 도달, 피해, 사망, 보상
- 몬스터 풀링
- 몬스터별 HP·속도·접촉 피해·보상 데이터
- 분열 몬스터와 보스가 확장될 수 있는 생명주기 훅

테스트 단위:

- L0: HP가 0 이하가 되면 한 번만 사망 처리되는가
- L1: 몬스터가 소환사에게 도달하면 피해를 주는가
- L1: 사망 보상이 중복 지급되지 않는가
- L1: 풀 반환 후 재사용 시 이전 상태가 남지 않는가

완료 기준: 기본 몬스터가 외곽에서 등장해 소환사에게 이동하고, 처치 또는 도달까지 한 사이클이 끝난다.

### F-04. 소환사 자동 공격

구현:

- 중앙 고정 위치
- 자동 타겟 선택
- 공격 간격과 사거리
- 원거리 투사체 발사
- 소환사 공격력·공격속도 데이터

테스트 단위:

- L0: 타겟 선택 우선순위가 일관적인가
- L1: 소환사가 이동하지 않고 자동 공격하는가
- L1: 사거리 밖 타겟을 무시하거나 접근하지 않는가
- L1: 투사체가 적에게 피해를 주는가

완료 기준: 유닛이 없어도 소환사만으로 기본 몬스터에게 자동 공격이 가능하다.

### F-05. 클릭 공격

구현:

- 화면 좌표 → 월드 좌표 변환
- 적을 클릭하면 해당 적을 향해 공격
- 빈 공간을 클릭하면 클릭 위치 방향으로 공격
- 자동 공격과 분리된 클릭 피해량·쿨다운
- 클릭 지점 표시와 타격 피드백

테스트 단위:

- L1: 필드 터치 한 번으로 공격이 발동하는가
- L1: 적 클릭 시 의도한 적을 우선 공격하는가
- L1: 빈 공간 클릭 시 클릭 방향으로 투사체가 나가는가
- L2: 짧은 터치와 드래그가 혼동되지 않는가

완료 기준: 자동 공격 중에도 플레이어가 클릭으로 특정 위치 또는 적을 직접 공격할 수 있다.

### F-06. 피해·속성·상태 효과

구현:

- 공격력, 방어 또는 피해 보정 계산
- 무·화염·빙결·자연 속성
- 상성 배율을 데이터 또는 설정값으로 관리
- 슬로우·도트·기절·분열 등 상태 효과 확장 지점

테스트 단위:

- L0: 유리·불리·중립 속성 배율이 정확한가
- L0: 무속성이 항상 중립 배율을 사용하는가
- L1: 상태 효과 지속시간과 중첩 규칙이 적용되는가
- L1: 피해 표시와 실제 HP 감소가 일치하는가

완료 기준: 유닛·소환사·몬스터가 공통 피해 계산기를 사용하고 수치가 하드코딩되지 않는다.

### F-07. 유닛 데이터와 전체 소환수 콘텐츠

구현:

- `UnitData` ScriptableObject
- 유닛 종류, 속성, 역할, 공격 방식, 사거리, 성급별 수치
- 기획서의 전체 고블린 유닛 연결
- 성급별 이름·능력·모디파이어
- 스프라이트·투사체·효과 참조

테스트 단위:

- L0: 모든 유닛 데이터가 필수 참조를 갖는가
- L0: 기본 → ★1 → ★2 → ★3 수치가 정상 증가하는가
- L1: 각 유닛이 자기 공격 방식으로 동작하는가
- L1: 데이터만 교체해 유닛을 추가할 수 있는가

완료 기준: 유닛별 개별 전투 코드를 새로 만들지 않고 전체 유닛을 데이터로 연결할 수 있다.

### F-08. 소환창·랜덤 소환·자동 배치

구현:

- 용병 계약서 보유량과 1장 차감
- 해금 풀에서 유닛 랜덤 선택
- 소환창 유닛 카드 드래그
- 소환 버튼 클릭 시 자동 배치
- 필드 유효 위치 판정과 겹침 방지
- 대기 유닛 목록 또는 벤치 용량 설정

테스트 단위:

- L0: 계약서 부족 시 소환되지 않는가
- L0: 시드가 같으면 랜덤 소환 결과를 재현할 수 있는가
- L1: 카드 드래그로 원하는 위치에 배치되는가
- L1: 소환 버튼으로 유효한 위치에 자동 배치되는가
- L2: 터치 드래그가 필드 좌표로 정확히 변환되는가

완료 기준: 소환창에서 직접 배치하거나 버튼으로 자동 배치할 수 있다.

### F-09. 자유 이동 소환수 AI

구현:

- 대기·탐색·이동·공격 상태
- 유닛별 타겟 우선순위
- 근접·원거리·범위·지원 역할
- 이동 중 재타겟팅
- 소환수 간 겹침과 필드 이탈 방지

테스트 단위:

- L0: 타겟 우선순위가 유닛 역할에 맞는가
- L1: 소환수가 적을 찾아 자유롭게 이동하는가
- L1: 사거리 진입 후 공격하는가
- L1: 적 사망 후 다음 타겟으로 전환하는가
- L2: 다수 소환수에서 프레임 저하가 허용 범위인지 확인

완료 기준: 고정 슬롯 없이 소환수가 필드 위에서 적을 찾아 처치한다.

### F-10. 소환수 재배치

구현:

- 필드 유닛 PointerDown/Move/Up 처리
- 드래그 고스트와 유효 위치 표시
- 전투 중 재배치
- 다른 유닛 위 드롭 시 머지 판정으로 전달

테스트 단위:

- L1: 드래그 중 유닛이 월드 좌표를 따라가는가
- L1: 필드 밖 또는 금지 위치에 놓을 수 없는가
- L1: 재배치 직후 AI가 정상적으로 재개되는가
- L2: 짧은 터치는 클릭 공격으로, 긴 이동은 드래그로 판정되는가

완료 기준: 전투 중 유닛을 원하는 위치로 이동시킬 수 있다.

### F-11. 인게임 3합성

구현:

- 같은 종류·같은 성급 3개 판정
- 유닛을 다른 유닛 위로 드래그했을 때 머지 후보 표시
- 필드·대기 목록을 포함한 세 번째 유닛 검색
- 세 유닛 제거와 상위 성급 생성
- 최대 성급 처리
- 머지 연출과 실패 피드백

테스트 단위:

- L0: 동일 조건 3개만 머지되는가
- L0: 서로 다른 종류·성급은 머지되지 않는가
- L0: 필드와 대기 목록의 유닛을 합쳐 판정할 수 있는가
- L1: 드래그 대상 위치에 상위 유닛이 생성되는가
- L1: 머지 중 피해·타겟 참조가 꼬이지 않는가

완료 기준: 플레이어가 전투 중 드래그 한 번으로 유효한 3합성을 실행할 수 있다.

### F-12. 웨이브 진행과 인터미션

구현:

- `StageTimeline`의 웨이브 순차 실행
- 준비 시간, 스폰, 웨이브 종료 판정
- 웨이브 보상
- 특성 선택 간격 판정
- 황금 고블린·행상인 이벤트 훅

테스트 단위:

- L0: 설정된 수량이 모두 스폰된 뒤 웨이브가 종료되는가
- L0: 설정된 간격에서만 특성 선택이 발생하는가
- L1: 전투 중 인터미션으로 잘못 진입하지 않는가
- L1: 마지막 웨이브 이후 승리 처리가 되는가

완료 기준: 웨이브 수와 이벤트가 `StageTimeline` 설정만으로 달라진다.

### F-13. 특성 3개 선택

구현:

- `TraitData` ScriptableObject
- 웨이브 간 3개 후보 생성
- 중복·획득 완료 특성 제외 규칙
- 선택 즉시 런 상태에 적용
- 공격력·공속·이동속도·소환·클릭·스킬 등 모디파이어

테스트 단위:

- L0: 후보가 3개 생성되는가
- L0: 선택한 특성이 한 번만 적용되는가
- L0: 최대 중첩과 중복 규칙이 지켜지는가
- L1: 선택 화면에서 전투가 멈추고 선택 후 재개되는가
- L1: 특성이 소환사와 소환수 수치에 실제로 반영되는가

완료 기준: 설정된 인터벌마다 3개 중 1개를 선택하고, 선택 효과가 런 종료까지 유지된다.

### F-14. 자동 스킬

구현:

- `SkillData` ScriptableObject
- 스킬 습득과 스킬 목록
- 쿨다운 충전
- 대상 규칙: 가장 가까운 적, 밀집 위치, 소환사 주변 등
- 메테오·빙결·버프 등 효과 확장
- 스킬 아이콘·쿨다운 표시

테스트 단위:

- L0: 스킬 쿨다운이 중복 발동하지 않는가
- L0: 대상 규칙에 따라 유효한 위치를 선택하는가
- L1: 습득한 스킬이 주기적으로 자동 발동하는가
- L1: 인터미션·승리·패배 중 스킬이 발동하지 않는가
- L2: 스킬 이펙트와 쿨다운 표시가 일치하는가

완료 기준: 플레이어가 습득한 스킬이 별도 버튼 조작 없이 설정된 주기로 사용된다.

### F-15. 황금 고블린

구현:

- 특수 몬스터 데이터
- 타임라인 또는 웨이브별 등장 확률·수량
- 일반 몬스터와 구분되는 시각 피드백
- 빠른 이동 또는 도주 규칙
- 처치 시 특별 골드 보상

테스트 단위:

- L0: 등장 확률과 최대 수량 설정이 지켜지는가
- L1: 황금 고블린이 일반 몬스터와 다른 행동을 하는가
- L1: 도주 전 처치 시 보상이 지급되는가
- L1: 도주 후 보상이 중복 지급되지 않는가

완료 기준: 황금 고블린이 런에 변수를 만들고, 플레이어가 처치할 이유가 있다.

### F-16. 행상인 비밀 상점

구현:

- 인터미션 등장 확률 또는 타임라인 지정
- 상품 데이터와 가격
- 골드 구매·품절·구매 불가 처리
- 구매하지 않고 닫기
- 런 전용 상품 효과

테스트 단위:

- L0: 등장 확률과 등장 웨이브 설정이 적용되는가
- L0: 상품 구매 후 골드와 재고가 정확히 갱신되는가
- L1: 상점이 전투 중 열리지 않는가
- L1: 구매 효과가 즉시 또는 지정 웨이브에 적용되는가
- L2: 터치로 구매·닫기가 안정적으로 동작하는가

완료 기준: 행상인이 인터미션에 등장하고, 골드로 런 중 상품을 구매할 수 있다.

### F-17. 경제와 보상

구현:

- 골드·용병 계약서 보유량
- 소환 계약서 비용
- 몬스터 처치 보상
- 웨이브 클리어 계약서 보상
- 유닛 판매 또는 교체
- 골드·계약서 부족 UI

테스트 단위:

- L0: 모든 증감 연산이 음수 잔액을 만들지 않는가
- L0: 보상이 한 번만 지급되는가
- L1: 소환은 계약서, 강화·판매·상점은 골드 경제를 정확히 사용하는가
- L1: HUD 표기와 실제 잔액이 일치하는가

완료 기준: 계약서 소환과 골드 강화 경제가 분리되고 웨이브 보상·전투·머지와 연결된다.

### F-18. 전체 몬스터 콘텐츠

구현:

- 기획서의 몬스터 형태 전체
- 형태별 행동: 기본, 고속, 탱크, 분열
- 속성 틴트와 속성 데이터
- 기획된 보스와 보스 페이즈
- `MonsterData`와 타임라인 연결

테스트 단위:

- L0: 모든 몬스터 데이터가 검증을 통과하는가
- L1: 형태별 행동 차이가 확인되는가
- L1: 분열 시 자식 몬스터가 정상 생성되는가
- L1: 보스 페이즈와 종료 조건이 동작하는가
- L2: 몬스터 수가 많은 웨이브에서 성능을 확인하는가

완료 기준: 기획서의 몬스터 콘텐츠를 새 전투 코드 없이 타임라인에 배치할 수 있다.

### F-19. UI 연결

구현:

- 웨이브 수를 타임라인에서 읽는 HUD
- 소환사 HP·골드·계약서·클릭 공격 피드백
- 소환창과 드래그 고스트
- 유닛 성급·속성·머지 가능 표시
- 특성 선택 패널
- 스킬 아이콘·쿨다운
- 행상인 상점
- 황금 고블린 경고·보상 표시
- 기존 방향 배지 UI 제거 또는 신규 외곽 경고로 교체

테스트 단위:

- L1: 게임 상태 변경이 UI에 이벤트로 반영되는가
- L1: 화면 전환 중 입력이 중복 처리되지 않는가
- L2: 1080×1920 기준과 실제 Android 안전 영역에서 터치 영역이 충분한가
- L2: 드래그·클릭·스크롤이 서로 오작동하지 않는가

완료 기준: UI는 게임 규칙을 직접 수정하지 않고 이벤트와 명령만 주고받는다.

### F-20. 런 종료·재시작·성능·빌드

구현:

- 소환사 HP 0 패배
- 타임라인 마지막 웨이브 클리어 승리
- 런 재시작과 런 데이터 초기화
- 몬스터·투사체 풀링
- Android 세로 고정과 실기기 빌드 검증

테스트 단위:

- L1: 승리·패배 화면이 정확한 조건에서 한 번만 표시되는가
- L1: 재시작 시 이전 유닛·골드·계약서·특성이 남지 않는가
- L2: 장시간 플레이 중 메모리와 FPS가 안정적인가
- L2: APK 설치·실행·터치·백그라운드 복귀를 확인하는가
- L3: 작은 타임라인과 큰 타임라인을 각각 끝까지 실행하는가

완료 기준: 실제 Android APK에서 임의의 스테이지를 시작해 승리 또는 패배까지 플레이할 수 있다.

## 5. 기능 구현 순서

날짜가 아닌 의존성 기준으로 다음 순서를 따른다.

### 그룹 A — 실행 기반

`F-01 → F-02 → F-03 → F-20 일부`

StageTimeline을 읽고, 외곽에서 몬스터가 등장해 소환사에게 도달하는 최소 런을 만든다.

### 그룹 B — 전투 기반

`F-04 → F-05 → F-06 → F-09 → F-18 일부`

소환사 자동 공격·클릭 공격과 자유 이동 소환수의 공통 전투 규칙을 만든다.

### 그룹 C — 플레이어 조작

`F-08 → F-10 → F-11 → F-17`

계약서 소환, 드래그 배치, 재배치, 머지, 골드 강화를 한 루프로 연결한다.

### 그룹 D — 웨이브 선택과 이벤트

`F-12 → F-13 → F-14 → F-15 → F-16`

인터미션 상태를 만들고 특성, 자동 스킬, 황금 고블린, 행상인을 연결한다.

### 그룹 E — 콘텐츠 연결

`F-07 → F-18 전체 → F-14 스킬 전체`

전체 유닛·몬스터·보스·속성·성급 데이터를 공통 시스템에 연결한다.

### 그룹 F — UI와 품질

`F-19 → F-20 전체 → F-03/F-09 풀링 최적화`

UI를 최신 규칙에 맞게 교체하고, Android 실기기에서 전체 런을 검증한다.

## 6. 기능 완료 판정 규칙

각 기능은 다음 조건을 모두 만족해야 완료로 표시한다.

1. 구현 코드가 있다.
2. 최소 하나의 자동 또는 수동 테스트 케이스가 있다.
3. 실패 케이스가 처리된다.
4. `StageTimeline` 또는 데이터 에셋으로 조정 가능한 값은 하드코딩하지 않는다.
5. 기존 기능을 깨뜨리지 않는 회귀 테스트를 통과한다.
6. Android에서 터치 또는 성능 문제가 없는지 확인한다.

## 7. 첫 번째 구현 묶음

가장 먼저 만들 기능 묶음은 다음이다.

```text
F-01 StageTimeline 실행
F-02 외곽 몬스터 스폰
F-03 몬스터 이동·도달 피해
F-04 소환사 자동 원거리 공격
F-05 클릭 공격
```

이 묶음의 테스트가 통과하면, 유닛·소환 UI를 붙이기 전에 **소환사가 직접 방어하는 기본 전투**가 성립한다.
