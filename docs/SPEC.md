- **대회 슬로건**: "AI의 다음 단계를 설계할 디렉터" — AI를 어디에 쓸지 판단한 설계력이 심사 포인트

**이 프로젝트의 3중 목표:**

## 1. 게임 컨셉

- **장르**: 십자형 타워 디펜스 × 로그라이크(메타 진행형) × 키우기
- **테마 (2026-07-11 확정)**: 인간 **소환사**(주인공)가 중앙 소환진에서 **고블린 용병단**을 소환해, 사방에서 밀려오는 **슬라임 군단**으로부터 **소환사 자신(=코어)**을 지킨다. 아군=고블린족 / 적=슬라임족으로 실루엣을 분리해 전장 가독성 확보. 적 종족 추가는 스코프 아웃(스펙 내에서는 슬라임만, 확장은 본선용)
- **한 줄 요약**: 중앙의 소환사를 지키기 위해 동서남북 4개 레인에 유닛을 소환·합성·배치하고, 웨이브 예고를 보고 유닛을 재배치하는 **방향 판단**이 핵심인 디펜스
- **1런 길이**: 15~20분, 웨이브 20개 + 보스(10웨이브마다), 20웨이브 클리어 시 승리
- **핵심 딜레마**: 자원은 한정, 지켜야 할 방향은 4개 → 웨이브 시작 전 방향별 예고를 보고 재배치할지 버틸지 결정

## 2. 핵심 시스템

### 2.1 필드
- 십자 맵: 중앙에 **소환사(주인공)가 직접 서 있음** — 발밑에 소환진 바닥 데칼 + 4방향 팔, 팔마다 유닛 슬롯 3칸 (총 12슬롯)
- **코어 = 소환사 본인 (2026-07-11 개정, 소환석 구조물 폐기)**: 지켜야 할 대상이 구조물이 아니라 소환사 자신. "코어 HP" = 소환사 HP (코드 식별자는 기존 core 유지 가능 — 일괄 리네임 금지)
- **런 흐름**: 런 시작 → 소환사 중앙 등장 → 준비 단계에서 **플레이어가 먼저 유닛을 소환·배치** → 웨이브 시작(몹 스폰)
- **유닛은 시즈 모드**: 배치된 슬롯에 완전 고정 — 스스로 이동·돌진·추격하지 않고, 사거리 안에 들어온 적만 자동 공격한다. 유닛의 위치가 바뀌는 방법은 오직 플레이어의 드래그 재배치뿐
- 적은 각 팔 끝에서 스폰되어 중앙 소환사에게 직진, 도달 시 소환사 HP 감소
- 소환사 HP 0 = 런 종료(패배)

### 2.2 소환·머지 (핵심 경제 루프 — 2026-07-14 계약서 경제로 개정)
- **소환 = 운빨**: 런 전용 재화 **용병 계약서 1장** 소모 → 해금된 고블린 풀에서 **종류 랜덤** 획득. 성급 없는 **기본 유닛**으로 등장
  - 골드는 몬스터 처치로 획득해 인게임 강화에만 사용하고, 소환 비용과 분리한다.
  - 계약서는 런 시작 시 **8~12장**을 지급하고, 일반 웨이브 클리어 시 **5~8장**, 5웨이브 단위 및 보스 클리어 시 **10~15장**을 지급한다. 정확한 수치는 웨이브 SO/밸런싱 CSV에서 조정한다.
  - 마지막 웨이브는 이후 소환 구간이 없으므로 계약서 대신 승리·보스 보상을 지급한다.
  - 낮은 확률(초기 ~5%)로 **★1 직행 잭팟** — 소환사 레벨/메타의 "소환 확률 개선" 스탯은 이 직행 확률을 올리는 것으로 재정의 (기존 등급 확률표 ★1 60/30/10은 폐기)
  - 연출: **슬롯머신 릴** (소환 탭 내). 3릴이 같은 유닛으로 정렬되면 ★1 직행 — 잭팟 확률을 슬롯 문법으로 시각화. 단 **로직 먼저, 릴 연출은 폴리싱 단계(3주차 이후)** — v1은 결과 즉시 표시 + 탭 스킵 가능해야 함 (소환을 수십 번 누르는 게임이므로 연출이 템포를 막으면 안 됨)
- **머지 (오토체스 3합성)**: 같은 종류 + 같은 성급 3개 = 성급 +1 유닛 1개. **기본 → ★1 → ★2 → ★3 (최대)**
  - ★3 1개 = 기본 27개 환산 — 한 런에서 ★3은 1~2개 뜨는 감도를 목표로 소환 비용 커브를 밸런싱 CSV에서 조정
  - 벤치/필드 어디에 있든 같은 것 3개가 모이면 합성 가능 (초록 테두리 + 합성 뱃지 → 탭 1번, §4.3)
- 벤치 12칸 (수치는 튜닝 가능), 벤치↔필드 드래그 배치/재배치
- 유닛 판매 가능 (소량의 골드 지급 — 벤치가 막힐 때의 배출구). 계약서는 환급하지 않아 판매→재소환 리롤 반복을 막는다.
- ⚠️ 해금 유닛이 늘수록 소환 풀 희석으로 머지 난도가 오름 — v1은 전체 풀 균등 랜덤으로 가고, 플레이테스트에서 희석이 체감될 때만 "런 시작 시 출전 덱 4~6종 선택"을 검토 (문제 확인 전에 미리 넣지 말 것)

### 2.3 유닛 — 고블린 용병단 (8종 확정)

| # | 유닛 | 역할 | 속성 | 해금 |
|---|---|---|---|---|
| 1 | 고블린 전사 | 근접 단일 (짧은 사거리·고딜, 제자리 스윙) | 무 | 기본 |
| 2 | 고블린 궁수 | 원거리 단일 투사체 | 무 | 기본 |
| 3 | 고블린 화염술사 | 범위 스플래시 | 화염 | 기본 |
| 4 | 고블린 냉기술사 | 슬로우 + 약딜 | 빙결 | 기본 |
| 5 | 고블린 독 주술사 | 지속딜 (독) | 자연 | 메타 해금 |
| 6 | 고블린 북잡이 | 같은 레인 아군 공속 버프 (비공격) | 무 | 메타 해금 |
| 7 | 고블린 폭탄병 | 광역 폭발 (짧은 사거리·고딜) | 화염 | 메타 해금 |
| 8 | 고블린 저격수 | 관통 장사거리 (빙정 화살) | 빙결 | 메타 해금 |

**성급 진화 — 성급마다 이름·능력이 바뀐다 (2026-07-11 확정)**

| 유닛 | 기본 → ★1 → ★2 → ★3 | 성급 킷 업그레이드 (기본 능력에 누적) |
|---|---|---|
| 전사 | 전사 → 기사 → 장군 → 워로드 | 동시 타격 대상 1→2→3마리, ★3: 타격 시 기절 확률 20% |
| 궁수 | 궁수 → 사수 → 명사수 → 신궁 | 연발 1→2→3발, ★3: 치명타 확률 30% |
| 화염술사 | 화염술사 → 화염도사 → 화염현자 → 화염제 | 폭발 반경 소→중→대, ★3: 화상 도트 부여 |
| 냉기술사 | 냉기술사 → 서리술사 → 빙결술사 → 빙하제 | 슬로우 20→30→40%, ★3: 확률 빙결(1초 정지) |
| 독 주술사 | 독 주술사 → 독 샤먼 → 역병 샤먼 → 역병군주 | 독 중첩 한도 1→2→3, ★3: 독 사망 시 주변 전염 |
| 북잡이 | 북잡이 → 북고수 → 군악대장 → 전쟁고수 | 레인 공속 버프 10→15→20%, ★3: 공격력 버프 +15% 추가 |
| 폭탄병 | 폭탄병 → 폭파병 → 폭파광 → 폭파왕 | 폭발 반경 증가, ★3: 처치 시 그 자리 2차 폭발(연쇄) |
| 저격수 | 저격수 → 감시자 → 처형자 → 서리사신 | 관통 2→3→4마리, ★3: 관통 피해 감소 없음(풀피해) |

- **성급업 = 스탯 점프(합산 3개분보다 세게, ×3.3~4 감도 — 밸런싱 CSV) + 킷 업그레이드 1개.** 역할 정체성은 유지 — 성급으로 역할이 바뀌는 리디자인 금지
- **구현은 파라미터 모디파이어로**: 대상 수/반경/연발/관통/슬로우율/중첩/버프량/확률 프록은 전부 UnitData SO의 성급별 수치 필드. 유닛×성급마다 개별 코드를 만들지 않는다
- ★3 전용 특수효과(전사 기절, 역병 전염, 폭파왕 연쇄 등)는 **스트레치 골** — 시간 부족 시 수치 강화로 폴백
- 성급별 스프라이트 재생성 금지 — 틴트 + 별 뱃지 오버레이 유지, 진화는 **이름·툴팁·이펙트**로 판다. 속성 정체성은 무기·소품 디자인에 고정
- 9~10번째 유닛(자연 속성 추가 등)은 3주차에 여유 있을 때만 — 기본은 8종 동결

### 2.4 성장 축 3개
1. **인게임 강화 (골드)**: 공격력/공속/소환사 HP 회복/치명타 — 키우기식 리스트에서 골드로 레벨업, 런 종료 시 리셋
2. **소환사 (주인공)**: 인게임 EXP로 레벨업 → 스탯 포인트/★1 직행(잭팟) 확률 개선. 스킬 개방과 아이템 장착의 주체
3. **메타 진행 (젬, 런 간 영구)**: 업그레이드 트리 15~20노드 — 시작 골드+, 시작 계약서+, 소환사 HP+, ★1 직행 확률+, 신규 유닛 해금. JSON + PlayerPrefs 저장

### 2.5 스킬 / 장비
- **스킬**: 웨이브 진행/소환사 레벨로 개방되는 액티브 스킬 (예: 메테오). 개방된 스킬은 필드 우하단 플로팅 버튼(쿨다운 표시)으로 노출
- **장비**: 웨이브 보상/보스 드랍 아이템을 유닛 또는 소환사에게 장착 (슬롯형 UI)

### 2.6 웨이브 설계 (규칙 기반 — 런타임 API 호출 없음)
- 웨이브 20개는 ScriptableObject 웨이브 테이블로 정의: 웨이브별 방향 가중치(N/E/S/W), 적 조합, 물량, HP 계수
- 방향 편중 패턴으로 재배치 딜레마 유도 (예: 초반 단일 방향 → 중반 2방향 동시 → 보스 전 4방향 분산)
- 난이도 곡선(적 HP/수량)은 지수 성장 기반, 테이블 수치는 LLM으로 CSV 생성 후 SO로 임포트 — **개발 도구로서의 AI 활용 사례로 기술 문서에 기록**
- 런마다 약간의 변주: 웨이브 테이블에 방향 가중치 ±랜덤 시드 적용 (로그라이크 반복 플레이 대응)

### 2.7 적 — 슬라임 군단 (형태 4종 × 속성 틴트)

| 형태 | 특성 | 속성 변형 |
|---|---|---|
| 노말 슬라임 | 표준 HP/속도 | 무·화염·빙결·자연 (틴트) |
| 스피드 슬라임 | 작고 빠름, 저HP | 〃 |
| 탱크 슬라임 | 크고 느림, 고HP | 〃 |
| 분열 슬라임 | 사망 시 소형 2마리로 분열 (속성 유지) | 〃 |

- 원본 이미지는 **형태 4종 × 1장(무속성 회백색 기준)만 생성**, 속성 변형은 틴트(빨강/파랑/초록) — 에셋 예산 절약
- 슬라임은 상하좌우 대칭에 가까운 실루엣 → 방향별 스프라이트 불필요. 이동 방향감은 DOTween 스쿼시&스트레치로 연출
- **보스 (전용 이미지 2장)**: 웨이브10 **킹 슬라임** (무속성 거대 + 잡몹 소환), 웨이브20 **마더 슬라임** (페이즈마다 속성 전환 → 막판 재배치 강제. 속성 전환이 부담되면 무속성 물량전으로 폴백)

### 2.8 속성 상성 (유닛 → 적 단방향)

- 속성 4종: **무(회색) / 화염(빨강) / 빙결(파랑) / 자연(초록)**
- 상성 고리: **화염 > 자연 > 빙결 > 화염**. 유닛의 공격 속성 → 적 속성으로만 적용 (적은 소환사만 공격하므로 역방향 상성 없음)
- 배율: 유리 **×1.5** / 불리 **×0.75** / 그 외 ×1.0. 무속성은 항상 ×1.0 (범용 안전픽 — 기본 해금 전사·궁수가 여기 해당)
- 웨이브 테이블(SO)에 방향별 적 속성 구성 필드 추가 → 런타임 스폰 규칙에 사용
- **설계 의도**: 상성은 재배치 딜레마의 정보축이다 — "동쪽에 화염 슬라임 예고 → 빙결 유닛을 동쪽으로 옮길까, 버틸까"가 매 웨이브의 판단이 되게 한다
- 배율 수치는 밸런싱 CSV/SO에서 조정 가능한 상수로 관리 (코드 하드코딩 금지)

## 3. 플랫폼·기술 스택

- **엔진**: Unity (2D, URP 불필요 시 Built-in)
- **빌드 타깃**: WebGL → GitHub Pages 배포 (심사 요건: 링크 클릭만으로 브라우저 플레이. PC exe 제출 불가)
- **화면**: 세로 1080×1920 고정. WebGL HTML 템플릿에서 9:16 캔버스 고정 + 레터박스
- **WebGL 필수 설정**:
  - Compression Format: Disabled 또는 Decompression Fallback ON (GitHub Pages가 Brotli/gzip 헤더 미지원)
  - 빌드 사이즈 목표 50MB 이하, 로딩 화면에 AI 생성 일러스트
  - 1주차에 큐브 하나로 빌드→Pages 배포→모바일 브라우저 실행까지 파이프라인 검증 (최우선 리스크)
- **UI**: UI Toolkit (UXML/USS) — HUD·하단 패널·배지 전담
  - PanelSettings: Reference Resolution 1080×1920, Scale With Screen Size, Match Width(0)
  - 유닛/몹/투사체/필드는 월드 오브젝트(SpriteRenderer) — UI Toolkit으로 필드를 그리지 말 것
  - 월드 앵커 UI(방향 배지 등)는 WorldToScreenPoint → 패널 좌표 변환으로 동기화
  - 드래그 앤 드롭(벤치 UI → 필드 월드): PointerDownEvent → UI 레이어 고스트 → PointerUpEvent에서 스크린 좌표 레이캐스트 → 월드 슬롯 스냅. 1~2주차에 우선 검증할 기술 리스크
- **연출**: 기본은 정적 스프라이트 + DOTween 코드 연출. 단, **슬라임 이동 포잉포잉과 기본 공격에 한해 각각 3×3 9프레임 스프라이트 시트를 허용**한다. 유닛은 시즈 모드(§2.1)이므로 위치가 이동하는 트윈(돌진 등)은 금지. 공격 시트는 주먹 전진·유지·복귀, 피격은 흰색 플래시
- **아키텍처 권장**: 웨이브/유닛/강화 데이터는 ScriptableObject, 투사체·몹은 오브젝트 풀링

- 컴포넌트별 uss 분리 (TopHUD.uss, BottomPanel.uss, UpgradeRow.uss)
- 위협도 색: danger(빨강)=위험 / warning(노랑)=보통 / muted(회색)=없음

### 3.4 코어 루프 착수 전 선행 작업 (이 순서대로)
1. WebGL 빌드 → GitHub Pages 배포 → 모바일 브라우저 실행 검증 (큐브 씬)
2. UI 스캐폴딩: 폴더 구조 + PanelSettings + RootLayout/TopHUD/BottomPanel 빈 껍데기 + variables.uss
3. **기술 스파이크 A**: 벤치(UI) → 필드(월드) 드래그 앤 드롭 브릿지 — 더미 슬롯 1개로 검증
4. **기술 스파이크 B**: TopHUD의 웨이브·잔여 몬스터 상태 표시가 세로 화면에서 읽히는지 검증

## 4. UI/UX 스펙 (v2 확정 — 키우기 문법 차용)

> 설계 원칙: "문법은 키우기류 차용, 스킨은 오리지널. 하단 패널은 키우기 문법, 필드는 배치형 디펜스 문법."
> 키우기류와 달리 필드가 '조작하는 곳'이므로 필드 존 비중을 크게 유지한다.

### 4.1 존 레이아웃 (세로 3분할)

| 존 | 비중 | 내용 |
|---|---|---|
| 상단 HUD | ~8% | 소환사 아이콘·닉네임·레벨, 스테이지명, 골드·젬 캡슐 2종, 설정 |
| 중앙 필드 | ~50% | 십자 맵(7×7 그리드 개념), 필드 상단 웨이브·잔여 몬스터, 스킬 플로팅 버튼(우하단) |
| 하단 패널 | ~40% | 탭 5개 + 탭 콘텐츠. 소환사 정보·EXP·강화는 소환사 탭에 배치 |

### 4.2 웨이브 상태 표시
- 방향 예고 배지(N/E/S/W)는 사용하지 않는다.
- HUD 아래 필드 상단 중앙에 현재 웨이브("WAVE 12")와 해당 웨이브 잔여 몬스터 수를 함께 표시한다.
- 웨이브 방향 가중치와 실제 적 스폰은 런타임 게임 로직에서 처리하며, 상단 HUD는 표시 전용이다.

### 4.3 하단 탭 5개
- **소환**: 실제 보유 유닛만 들어가는 벤치 12슬롯(합성 가능 시 초록 테두리+"합성" 뱃지) + `보유 용병 n/12` + 용병 계약서 보유량 + `소환 ×1` 버튼(우측 엄지 위치) + ★1 직행 확률 노출. 전체 8종을 선택 슬롯처럼 상시 나열하지 않는다(선택 소환 오인 방지). 슬롯머신 릴 연출은 폴리싱 단계에 추가 (§2.2)
  - 합성 뱃지/프리뷰에 **다음 성급 진화 이름** 노출 (예: "기사 → 장군") — 진화 서사를 파는 지점 (§2.3)
- **강화**: 키우기식 리스트 행 [아이콘 | 스탯명+Lv | 현재→다음 수치 | 골드 버튼]. 골드 부족 시 버튼 회색 비활성. 길게 누르면 연속 강화
- **스킬**: 같은 리스트 행 구조, 버튼이 "개방"으로 변경
- **장비**: 슬롯형 (유닛/소환사 선택 → 장착 슬롯)
- **소환사**: 상단 프로필(초상화·Lv·EXP·강화) + 같은 리스트 행 구조(소환사 스탯) + 메타 트리 입구
- 탭에 레드닷: 강화 가능/새 장비 획득 시
- 리스트 행은 UXML 템플릿 1개 + 데이터 바인딩으로 재사용 (강화/스킬/소환사 3탭 공용)
- 탭 열면 하단 패널 확장 + 필드 축소, 단 전투는 계속 보이게

### 4.4 소환사 탭 프로필
- 별도 상시 노출 SummonerStrip은 사용하지 않는다. TopHUD의 소환사 프로필과 정보가 중복되고 탭 콘텐츠 높이를 소모하기 때문이다.
- 초상화 + Lv + EXP바 + 강화 버튼은 SummonerTab 상단 프로필 영역에서만 표시한다.

### 4.5 기타 키우기 문법
- 소환 이펙트: 일반 소환은 가볍게, ★1 직행 잭팟은 금색 강조. 머지 성공 시 성급 상승 이펙트
- 골드·계약서 등 필요한 재화가 부족하면 버튼을 회색 처리하고, 수치는 항상 "현재→다음" 변화량 표기

## 5. AI 에셋 파이프라인

### 5.1 3단 프롬프트 아키텍처 (기술 문서의 뼈대)

> **2026-07-11 v2 확정: 픽셀 아트로 전면 전환.** v1(SD 셀셰이딩)은 레퍼런스(픽셀 방치형 디펜스, 척박한 숲 개간지) 대비 톤 불일치로 폐기 — 사례: `prompt-cases/case-01-style-anchor/`. **아트 무드: 척박한 숲 한가운데 개간지에서 시작** (마른 풀·죽은 나무·바랜 흙, 채도 낮은 어스 톤).

```

cute chibi pixel art game asset, 16-bit retro RPG style,
big head small body, 1px dark outline, muted earthy palette,
```

레이어 3(개체 변수)은 v1과 동일: `{unit_concept}` = "goblin archer with short bow" 등.

4. **AI 활용 기술 문서 PDF** — 3단 프롬프트 아키텍처 다이어그램, 카테고리별 템플릿·변수 표, 개선 사례 2~3개(before/after), 사용 기법 명명(few-shot, negative prompt 등), 코드·에셋·밸런싱·사운드 영역별 활용 내역, 외부 에셋·오픈소스 출처/라이선스 전부 명시
5. **팀원 롤 기술서** — 1인 참여 시 생략
