# 십자 디펜스 (Cross Defense) — 프로젝트 스펙

> NAN 2026 (NHN Game × AI Hackathon) 사전 과제 제출작. **이 문서가 프로젝트의 단일 기준(Single Source of Truth)이다.**

## 0. 컨텍스트와 목표

- **대회**: NAN 2026, 사전 과제 심사로 10팀 선발 → 본선은 9/4~9/6 주제 현장 공개 48시간 해커톤 (NHN 사옥, 오프라인)
- **사전 과제 마감**: 2026-08-10 (접수 마감 후 수정 불가)
- **개발 기간**: 2026-07-11 ~ 08-10 (약 30일), 1인 개발
- **대회 슬로건**: "AI의 다음 단계를 설계할 디렉터" — AI를 어디에 쓸지 판단한 설계력이 심사 포인트

**이 프로젝트의 3중 목표:**
1. 10팀 안에 드는 사전 과제 (게임 완성도 + AI 활용 문서화)
2. 본선 48시간용 재사용 자산 축적 (Unity 보일러플레이트, 프롬프트 템플릿, LLM 연동 모듈)
3. 커밋 기록 자체가 "한 달의 AI 활용 과정" 증거가 되도록 관리

## 1. 게임 컨셉

- **장르**: 십자형 타워 디펜스 × 로그라이크(메타 진행형) × 키우기
- **한 줄 요약**: 중앙 코어를 지키기 위해 동서남북 4개 레인에 유닛을 소환·합성·배치하고, 웨이브 예고를 보고 유닛을 재배치하는 **방향 판단**이 핵심인 디펜스
- **1런 길이**: 15~20분, 웨이브 20개 + 보스(10웨이브마다), 20웨이브 클리어 시 승리
- **핵심 딜레마**: 자원은 한정, 지켜야 할 방향은 4개 → 웨이브 시작 전 방향별 예고를 보고 재배치할지 버틸지 결정

## 2. 핵심 시스템

### 2.1 필드
- 십자 맵: 중앙 코어 + 4방향 팔, 팔마다 유닛 슬롯 3칸 (총 12슬롯)
- 적은 각 팔 끝에서 스폰되어 코어로 직진, 코어 도달 시 코어 HP 감소
- 코어 HP 0 = 런 종료(패배)

### 2.2 소환·합성 (핵심 경제 루프)
- 골드로 유닛 소환 (등급 확률: ★1 60% / ★2 30% / ★3 10%, 소환사 레벨로 확률 개선)
- 같은 유닛 3개 = 상위 등급 1개로 합성 (오토체스 방식)
- 벤치(대기석)와 필드 슬롯 간 드래그 배치/재배치
- 유닛 판매 가능

### 2.3 유닛 (8~10종, 역할 분화)
- 단일 투사체(궁수/검사), 범위 공격(화염), 슬로우(빙결), 버프(지원) 등 역할군으로 설계
- 기본 4종 해금 상태, 나머지는 메타 진행으로 해금
- 등급별 색 변형은 Unity 틴트로 처리 (이미지 재생성 금지)

### 2.4 성장 축 3개
1. **인게임 강화 (골드)**: 공격력/공속/코어 회복/치명타 — 키우기식 리스트에서 골드로 레벨업, 런 종료 시 리셋
2. **소환사 (주인공)**: 인게임 EXP로 레벨업 → 스탯 포인트/소환 확률 개선. 스킬 개방과 아이템 장착의 주체
3. **메타 진행 (젬, 런 간 영구)**: 업그레이드 트리 15~20노드 — 시작 골드+, 코어 HP+, 리롤 비용-, 신규 유닛 해금. JSON + PlayerPrefs 저장

### 2.5 스킬 / 장비
- **스킬**: 웨이브 진행/소환사 레벨로 개방되는 액티브 스킬 (예: 메테오). 개방된 스킬은 필드 우하단 플로팅 버튼(쿨다운 표시)으로 노출
- **장비**: 웨이브 보상/보스 드랍 아이템을 유닛 또는 소환사에게 장착 (슬롯형 UI)

### 2.6 LLM 웨이브 디렉터 (인게임 AI — 차별화 요소)
- 플레이어의 유닛 배치/성과 데이터를 웨이브 사이에 LLM API로 전송 → 다음 웨이브의 방향별 물량·조합을 AI가 동적 설계
- 컨셉: "AI 던전마스터가 당신의 약점을 노린다"
- **보안 필수**: WebGL 클라이언트에서 API 직접 호출 금지. Cloudflare Workers 무료 티어 프록시 경유 (API 키는 Workers 환경변수)
- 호출량 부담 시 폴백: 런 시작 시 1회 호출로 축소, 또는 로컬 규칙 기반 폴백 (API 실패 시에도 게임은 돌아가야 함)
- 응답은 JSON 강제 (system prompt에 "JSON only" 명시, 파싱 실패 시 재시도 1회 후 폴백)

## 3. 플랫폼·기술 스택

- **엔진**: Unity (2D, URP 불필요 시 Built-in)
- **빌드 타깃**: WebGL → GitHub Pages 배포 (심사 요건: 링크 클릭만으로 브라우저 플레이. PC exe 제출 불가)
- **화면**: 세로 1080×1920 고정. WebGL HTML 템플릿에서 9:16 캔버스 고정 + 레터박스
- **WebGL 필수 설정**:
  - Compression Format: Disabled 또는 Decompression Fallback ON (GitHub Pages가 Brotli/gzip 헤더 미지원)
  - 빌드 사이즈 목표 50MB 이하, 로딩 화면에 AI 생성 일러스트
  - 1주차에 큐브 하나로 빌드→Pages 배포→모바일 브라우저 실행까지 파이프라인 검증 (최우선 리스크)
- **UI**: UI Toolkit (UXML/USS) — HUD·하단 패널·배지 전담
  - PanelSettings: Reference Resolution 1080×1920, Scale With Screen Size, Match Width(0)
  - 유닛/몹/투사체/필드는 월드 오브젝트(SpriteRenderer) — UI Toolkit으로 필드를 그리지 말 것
  - 월드 앵커 UI(방향 배지 등)는 WorldToScreenPoint → 패널 좌표 변환으로 동기화
  - 드래그 앤 드롭(벤치 UI → 필드 월드): PointerDownEvent → UI 레이어 고스트 → PointerUpEvent에서 스크린 좌표 레이캐스트 → 월드 슬롯 스냅. 1~2주차에 우선 검증할 기술 리스크
- **연출**: 프레임 애니메이션 없음. 정적 스프라이트 + DOTween 코드 연출 (공격 시 돌진 트윈, 피격 흰색 플래시, 스쿼시&스트레치)
- **아키텍처 권장**: 웨이브/유닛/강화 데이터는 ScriptableObject, 투사체·몹은 오브젝트 풀링

## 4. UI/UX 스펙 (v2 확정 — 키우기 문법 차용)

> 설계 원칙: "문법은 키우기류 차용, 스킨은 오리지널. 하단 패널은 키우기 문법, 필드는 배치형 디펜스 문법."
> 키우기류와 달리 필드가 '조작하는 곳'이므로 필드 존 비중을 크게 유지한다.

### 4.1 존 레이아웃 (세로 3분할)

| 존 | 비중 | 내용 |
|---|---|---|
| 상단 HUD | ~8% | Wave 12/20, 코어 HP바, 골드·젬 캡슐 2종, 설정 |
| 중앙 필드 | ~50% | 십자 맵(7×7 그리드 개념), 방향별 웨이브 예고 배지, 스킬 플로팅 버튼(우하단) |
| 하단 패널 | ~40% | 탭 5개 + 탭 콘텐츠 + 소환사 스트립(상시 노출) |

### 4.2 방향 예고 배지 (이 게임의 최중요 UI)
- 각 레인 끝에 "N ×24" 형식, 위협도 색 인코딩: 빨강=위험 / 노랑=보통 / 회색=없음
- 절대 하단 패널에 묻지 말 것

### 4.3 하단 탭 5개
- **소환**: 벤치 슬롯(합성 가능 시 초록 테두리+"합성" 뱃지) + 소환 버튼(비용 표시, 우측 엄지 위치) + 등급 확률 노출
- **강화**: 키우기식 리스트 행 [아이콘 | 스탯명+Lv | 현재→다음 수치 | 골드 버튼]. 골드 부족 시 버튼 회색 비활성. 길게 누르면 연속 강화
- **스킬**: 같은 리스트 행 구조, 버튼이 "개방"으로 변경
- **장비**: 슬롯형 (유닛/소환사 선택 → 장착 슬롯)
- **소환사**: 같은 리스트 행 구조(소환사 스탯) + 메타 트리 입구
- 탭에 레드닷: 강화 가능/새 장비 획득 시
- 리스트 행은 UXML 템플릿 1개 + 데이터 바인딩으로 재사용 (강화/스킬/소환사 3탭 공용)
- 탭 열면 하단 패널 확장 + 필드 축소, 단 전투는 계속 보이게

### 4.4 소환사 스트립 (최하단 상시 노출)
- 초상화 + Lv + EXP바 + 강화 버튼. 어느 탭에서든 보임

### 4.5 기타 키우기 문법
- 소환 등급별 색 이펙트 (일반 회색 → 영웅 보라 → 전설 금)
- 재화 부족 시 버튼 회색 처리, 수치는 항상 "현재→다음" 변화량 표기

## 5. AI 에셋 파이프라인

### 5.1 3단 프롬프트 아키텍처 (기술 문서의 뼈대)

```
[레이어 1: 스타일 앵커 — 전 에셋 공통]
chibi fantasy game asset, thick dark outline, flat cel shading,
solid green background (#00FF00), centered, full body view

[레이어 2: 카테고리 변수 — 예: 유닛]
+ single {unit_concept}, facing right, idle pose, weapon visible

[레이어 3: 개체 변수]
{unit_concept} = "frost archer with ice bow" / "flame golem" / ...
```

- 배경은 크로마키 그린으로 뽑아 제거
- 여러 유닛을 한 장에 그리드로 생성 후 잘라 쓰는 방식도 일관성에 유효

### 5.2 도구 분담
- 이미지: ChatGPT 이미지 생성 / 사운드 BGM: Suno / SFX: ElevenLabs 또는 jsfxr / 코드: Claude Code / 밸런스 테이블: LLM으로 CSV 생성

### 5.3 필요 에셋 목록 (~50장 이내)
- 유닛 8~10종(등급 색변형은 틴트), 적 6~8종 + 보스 2종, 코어 1개(피격 단계 2~3장), 타일/바닥, UI 아이콘 ~20개, 타이틀 일러스트 1장, 로딩 일러스트 1장

### 5.4 기록 의무 (제출 요건 직결)
- **에셋 대장** 스프레드시트를 1일차부터 기록: 파일명 / 생성 도구 / 사용 프롬프트 / 라이선스·출처 → [docs/asset-ledger.csv](asset-ledger.csv)
- 프롬프트 실패→개선 사례(v1→v2→v3)를 겪을 때마다 스크린샷으로 보존 → `docs/prompt-cases/`
- 커밋 메시지에 AI 활용 흔적 남기기 (예: `feat: AI-generated unit sprites integrated`)

## 6. 4주 일정 (7/11 ~ 8/10)

### 1주차 — 파이프라인 + 코어 루프
- **[최우선]** 저장소 생성, Unity WebGL 빌드 → GitHub Pages 배포 → 모바일 브라우저 검증
- 십자 맵, 몹 스폰/이동/코어 공격, 유닛 배치·자동 공격, 웨이브 시스템
- 벤치→필드 드래그 앤 드롭 기술 검증 (UI Toolkit ↔ 월드 브릿지)
- 스타일 앵커 프롬프트 확정 (유닛 2~3개 테스트 생성), 에셋 대장 시작
- 목표: "재미없어도 돌아가는" 상태

### 2주차 — 로그라이크 + 키우기 살
- 상점/골드/합성, 유닛 8~10종, 방향별 웨이브 예고 + 재배치
- 강화 탭(리스트 행 컴포넌트), 탭 프레임 5개
- 에셋 일괄 생성 데이 1일 (임시 네모 스프라이트 → 일괄 교체)
- 주말: WebGL 배포 링크로 재미 검증 1차

### 3주차 — 메타 + AI 디렉터 + 보스
- LLM 웨이브 디렉터 (Cloudflare Workers 프록시 포함)
- 메타 진행 트리, 저장/로드, 소환사 스킬/장비, 보스 2종, 사운드
- 배포 링크로 지인 플레이테스트

### 4주차 — 동결 + 폴리싱 + 제출
- 신규 기능 추가 금지. 타격감/이펙트(영상 컷 기준 우선순위), 밸런싱, 로딩 최적화, 튜토리얼(첫 런 가이드)
- 8/6~7: 플레이 영상 촬영·편집 / 8/7~8: 문서 3종 작성 / 8/9: 제출 / 8/10: 버퍼

## 7. 제출물 체크리스트 (5종, 하나라도 누락 시 탈락)

1. **플레이 빌드 + 소스** — WebGL을 GitHub Pages로, 소스 전체 동일 저장소, 커밋 기록 유지, public 권장 (비공개 시 심사 계정 dl_gameai_reviewer@nhn.com 초대). 유료 라이선스 없이 실행 가능해야 함
2. **플레이 영상** — YouTube 30~60초, 실제 플레이 화면만(AI 합성·조작 불가). 컷 구성안: 타이틀 3s → 배치+전투 20s → 예고 보고 재배치 15s → 합성/성장 10s → 보스 10s
3. **게임 소개 PDF** — 제목·한 줄 소개, 게임 방법(목표/조작/종료 조건), 실행 방법, 플레이 링크, 영상 링크
4. **AI 활용 기술 문서 PDF** — 3단 프롬프트 아키텍처 다이어그램, 카테고리별 템플릿·변수 표, 개선 사례 2~3개(before/after), 사용 기법 명명(few-shot, negative prompt 등), 웨이브 디렉터 시스템 아키텍처, 코드·에셋·밸런싱·사운드 영역별 활용 내역, 외부 에셋·오픈소스 출처/라이선스 전부 명시
5. **팀원 롤 기술서** — 1인 참여 시 생략

## 8. 스코프에서 제외 (하지 말 것)
