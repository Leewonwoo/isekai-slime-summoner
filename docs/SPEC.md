# 십자 디펜스 (Cross Defense) — 프로젝트 스펙

> NAN 2026 (NHN Game × AI Hackathon) 사전 과제 제출작. **이 문서가 프로젝트의 단일 기준(Single Source of Truth)이다.**

## 0. 컨텍스트와 목표

- **대회**: NAN 2026, 사전 과제 심사로 10팀 선발 → 본선은 9/4~9/6 주제 현장 공개 48시간 해커톤 (NHN 사옥, 오프라인)
- **사전 과제 마감**: 2026-08-10 (접수 마감 후 수정 불가)
- **개발 기간**: 2026-07-11 ~ 08-10 (약 30일), 1인 개발
- **대회 슬로건**: "AI의 다음 단계를 설계할 디렉터" — AI를 어디에 쓸지 판단한 설계력이 심사 포인트

**이 프로젝트의 3중 목표:**
1. 10팀 안에 드는 사전 과제 (게임 완성도 + AI 활용 문서화)
2. 본선 48시간용 재사용 자산 축적 (Unity 보일러플레이트, 프롬프트 템플릿)
3. 커밋 기록 자체가 "한 달의 AI 활용 과정" 증거가 되도록 관리

## 1. 게임 컨셉

- **장르**: 십자형 타워 디펜스 × 로그라이크(메타 진행형) × 키우기
- **테마 (2026-07-11 확정)**: 인간 **소환사**(주인공)가 중앙 소환진에서 **고블린 용병단**을 소환해, 사방에서 밀려오는 **슬라임 군단**으로부터 소환진(코어)을 지킨다. 아군=고블린족 / 적=슬라임족으로 실루엣을 분리해 전장 가독성 확보. 적 종족 추가는 스코프 아웃(스펙 내에서는 슬라임만, 확장은 본선용)
- **한 줄 요약**: 중앙 코어를 지키기 위해 동서남북 4개 레인에 유닛을 소환·합성·배치하고, 웨이브 예고를 보고 유닛을 재배치하는 **방향 판단**이 핵심인 디펜스
- **1런 길이**: 15~20분, 웨이브 20개 + 보스(10웨이브마다), 20웨이브 클리어 시 승리
- **핵심 딜레마**: 자원은 한정, 지켜야 할 방향은 4개 → 웨이브 시작 전 방향별 예고를 보고 재배치할지 버틸지 결정

## 2. 핵심 시스템

### 2.1 필드
- 십자 맵: 중앙 코어 + 4방향 팔, 팔마다 유닛 슬롯 3칸 (총 12슬롯)
- 적은 각 팔 끝에서 스폰되어 코어로 직진, 코어 도달 시 코어 HP 감소
- 코어 HP 0 = 런 종료(패배)

### 2.2 소환·합성 (핵심 경제 루프)
- 골드로 유닛 소환 (등급 확률: ★1 60% / ★2 30% / ★3 10%, 소환사 레벨로 확률 개선)
- 같은 유닛 3개 = 상위 등급 1개로 합성 (오토체스 방식)
- 벤치(대기석)와 필드 슬롯 간 드래그 배치/재배치
- 유닛 판매 가능

### 2.3 유닛 — 고블린 용병단 (8종 확정)

| # | 유닛 | 역할 | 속성 | 해금 |
|---|---|---|---|---|
| 1 | 고블린 전사 | 근접 단일 (돌진 트윈) | 무 | 기본 |
| 2 | 고블린 궁수 | 원거리 단일 투사체 | 무 | 기본 |
| 3 | 고블린 화염술사 | 범위 스플래시 | 화염 | 기본 |
| 4 | 고블린 냉기술사 | 슬로우 + 약딜 | 빙결 | 기본 |
| 5 | 고블린 독 주술사 | 지속딜 (독) | 자연 | 메타 해금 |
| 6 | 고블린 북잡이 | 같은 레인 아군 공속 버프 (비공격) | 무 | 메타 해금 |
| 7 | 고블린 폭탄병 | 광역 폭발 (짧은 사거리·고딜) | 화염 | 메타 해금 |
| 8 | 고블린 저격수 | 관통 장사거리 (빙정 화살) | 빙결 | 메타 해금 |

- 등급별(★1→★3) 색 변형은 Unity 틴트로 처리 (이미지 재생성 금지). 속성 정체성은 무기·소품 디자인에 고정하고, 등급은 틴트로만 구분
- 9~10번째 유닛(자연 속성 추가 등)은 3주차에 여유 있을 때만 — 기본은 8종 동결

### 2.4 성장 축 3개
1. **인게임 강화 (골드)**: 공격력/공속/코어 회복/치명타 — 키우기식 리스트에서 골드로 레벨업, 런 종료 시 리셋
2. **소환사 (주인공)**: 인게임 EXP로 레벨업 → 스탯 포인트/소환 확률 개선. 스킬 개방과 아이템 장착의 주체
3. **메타 진행 (젬, 런 간 영구)**: 업그레이드 트리 15~20노드 — 시작 골드+, 코어 HP+, 리롤 비용-, 신규 유닛 해금. JSON + PlayerPrefs 저장

### 2.5 스킬 / 장비
- **스킬**: 웨이브 진행/소환사 레벨로 개방되는 액티브 스킬 (예: 메테오). 개방된 스킬은 필드 우하단 플로팅 버튼(쿨다운 표시)으로 노출
- **장비**: 웨이브 보상/보스 드랍 아이템을 유닛 또는 소환사에게 장착 (슬롯형 UI)

### 2.6 웨이브 설계 (규칙 기반 — 런타임 API 호출 없음)
- 웨이브 20개는 ScriptableObject 웨이브 테이블로 정의: 웨이브별 방향 가중치(N/E/S/W), 적 조합, 물량, HP 계수
- 방향 편중 패턴으로 재배치 딜레마 유도 (예: 초반 단일 방향 → 중반 2방향 동시 → 보스 전 4방향 분산)
- 난이도 곡선(적 HP/수량)은 지수 성장 기반, 테이블 수치는 LLM으로 CSV 생성 후 SO로 임포트 — **개발 도구로서의 AI 활용 사례로 기술 문서에 기록**
- 런마다 약간의 변주: 웨이브 테이블에 방향 가중치 ±랜덤 시드 적용 (로그라이크 반복 플레이 대응)

### 2.7 적 — 슬라임 군단 (형태 4종 × 속성 틴트)

| 형태 | 특성 | 속성 변형 |
|---|---|---|
| 노말 슬라임 | 표준 HP/속도 | 무·화염·빙결·자연 (틴트) |
| 스피드 슬라임 | 작고 빠름, 저HP | 〃 |
| 탱크 슬라임 | 크고 느림, 고HP | 〃 |
| 분열 슬라임 | 사망 시 소형 2마리로 분열 (속성 유지) | 〃 |

- 원본 이미지는 **형태 4종 × 1장(무속성 회백색 기준)만 생성**, 속성 변형은 틴트(빨강/파랑/초록) — 에셋 예산 절약
- 슬라임은 상하좌우 대칭에 가까운 실루엣 → 방향별 스프라이트 불필요. 이동 방향감은 DOTween 스쿼시&스트레치로 연출
- **보스 (전용 이미지 2장)**: 웨이브10 **킹 슬라임** (무속성 거대 + 잡몹 소환), 웨이브20 **마더 슬라임** (페이즈마다 속성 전환 → 막판 재배치 강제. 속성 전환이 부담되면 무속성 물량전으로 폴백)

### 2.8 속성 상성 (유닛 → 적 단방향)

- 속성 4종: **무(회색) / 화염(빨강) / 빙결(파랑) / 자연(초록)**
- 상성 고리: **화염 > 자연 > 빙결 > 화염**. 유닛의 공격 속성 → 적 속성으로만 적용 (적은 코어만 공격하므로 역방향 상성 없음)
- 배율: 유리 **×1.5** / 불리 **×0.75** / 그 외 ×1.0. 무속성은 항상 ×1.0 (범용 안전픽 — 기본 해금 전사·궁수가 여기 해당)
- 웨이브 테이블(SO)에 방향별 적 속성 구성 필드 추가 → 방향 예고 배지에 지배 속성 아이콘 노출 (§4.2)
- **설계 의도**: 상성은 재배치 딜레마의 정보축이다 — "동쪽에 화염 슬라임 예고 → 빙결 유닛을 동쪽으로 옮길까, 버틸까"가 매 웨이브의 판단이 되게 한다
- 배율 수치는 밸런싱 CSV/SO에서 조정 가능한 상수로 관리 (코드 하드코딩 금지)

## 3. 플랫폼·기술 스택

- **엔진**: Unity (2D, URP 불필요 시 Built-in)
- **빌드 타깃**: WebGL → GitHub Pages 배포 (심사 요건: 링크 클릭만으로 브라우저 플레이. PC exe 제출 불가)
- **화면**: 세로 1080×1920 고정. WebGL HTML 템플릿에서 9:16 캔버스 고정 + 레터박스
- **WebGL 필수 설정**:
  - Compression Format: Disabled 또는 Decompression Fallback ON (GitHub Pages가 Brotli/gzip 헤더 미지원)
  - 빌드 사이즈 목표 50MB 이하, 로딩 화면에 AI 생성 일러스트
  - 1주차에 큐브 하나로 빌드→Pages 배포→모바일 브라우저 실행까지 파이프라인 검증 (최우선 리스크)
- **UI**: UI Toolkit (UXML/USS) — HUD·하단 패널·배지 전담
  - PanelSettings: Reference Resolution 1080×1920, Scale With Screen Size, Match Width(0)
  - 유닛/몹/투사체/필드는 월드 오브젝트(SpriteRenderer) — UI Toolkit으로 필드를 그리지 말 것
  - 월드 앵커 UI(방향 배지 등)는 WorldToScreenPoint → 패널 좌표 변환으로 동기화
  - 드래그 앤 드롭(벤치 UI → 필드 월드): PointerDownEvent → UI 레이어 고스트 → PointerUpEvent에서 스크린 좌표 레이캐스트 → 월드 슬롯 스냅. 1~2주차에 우선 검증할 기술 리스크
- **연출**: 프레임 애니메이션 없음. 정적 스프라이트 + DOTween 코드 연출 (공격 시 돌진 트윈, 피격 흰색 플래시, 스쿼시&스트레치)
- **아키텍처 권장**: 웨이브/유닛/강화 데이터는 ScriptableObject, 투사체·몹은 오브젝트 풀링

### 3.1 프로젝트 폴더 구조

```
Assets/
  Scripts/
    Core/        # GameManager, WaveManager, EconomyManager
    Units/       # 유닛/몹/투사체 (월드 오브젝트)
    UI/          # UI Toolkit 컨트롤러 (C#)
    Data/        # ScriptableObject 정의
  UI/
    UXML/        # 레이아웃
    USS/         # 스타일
  Data/          # SO 인스턴스 (유닛, 웨이브, 강화 테이블)
  Art/           # AI 생성 스프라이트 (에셋 대장과 파일명 일치)
  Audio/
```

### 3.2 UXML 구조 (이 구조를 벗어나지 말 것)

```
RootLayout.uxml
 ├─ TopHUD.uxml          # 웨이브/코어HP/재화 — 데이터 바인딩만
 ├─ FieldOverlay.uxml    # absolute 레이어: 방향 예고 배지 4개, 스킬 플로팅 버튼
 │                       #   (월드 앵커 → WorldToScreenPoint 동기화)
 └─ BottomPanel.uxml
     ├─ TabBar (5탭 + 레드닷)
     ├─ TabContent: SummonTab / UpgradeTab / SkillTab / GearTab / SummonerTab
     │   각각 별도 .uxml, 런타임 교체
     │   UpgradeTab·SkillTab·SummonerTab은 UpgradeRow.uxml 템플릿 공용
     │   (아이콘|이름+Lv|현재→다음|버튼) + 데이터 바인딩
     └─ SummonerStrip (상시 노출)
```

### 3.3 USS 규칙
- `variables.uss`에 전 색상/간격을 CSS 변수로 정의 (`--color-danger`, `--color-warning`, `--gap-sm` 등). **하드코딩 색상 금지**
- 컴포넌트별 uss 분리 (TopHUD.uss, BottomPanel.uss, UpgradeRow.uss)
- 위협도 색: danger(빨강)=위험 / warning(노랑)=보통 / muted(회색)=없음

### 3.4 코어 루프 착수 전 선행 작업 (이 순서대로)
1. WebGL 빌드 → GitHub Pages 배포 → 모바일 브라우저 실행 검증 (큐브 씬)
2. UI 스캐폴딩: 폴더 구조 + PanelSettings + RootLayout/TopHUD/BottomPanel 빈 껍데기 + variables.uss
3. **기술 스파이크 A**: 벤치(UI) → 필드(월드) 드래그 앤 드롭 브릿지 — 더미 슬롯 1개로 검증
4. **기술 스파이크 B**: 월드 앵커 배지 1개가 WorldToScreenPoint로 필드 위치에 붙는지 검증
5. 여기까지 통과 후 코어 루프(스폰/이동/공격/웨이브) 착수

> 스파이크 A/B가 막히면 코어 루프보다 먼저 해결한다 — UI 아키텍처 전체가 여기 걸려 있음

## 4. UI/UX 스펙 (v2 확정 — 키우기 문법 차용)

> 설계 원칙: "문법은 키우기류 차용, 스킨은 오리지널. 하단 패널은 키우기 문법, 필드는 배치형 디펜스 문법."
> 키우기류와 달리 필드가 '조작하는 곳'이므로 필드 존 비중을 크게 유지한다.

### 4.1 존 레이아웃 (세로 3분할)

| 존 | 비중 | 내용 |
|---|---|---|
| 상단 HUD | ~8% | Wave 12/20, 코어 HP바, 골드·젬 캡슐 2종, 설정 |
| 중앙 필드 | ~50% | 십자 맵(7×7 그리드 개념), 방향별 웨이브 예고 배지, 스킬 플로팅 버튼(우하단) |
| 하단 패널 | ~40% | 탭 5개 + 탭 콘텐츠 + 소환사 스트립(상시 노출) |

### 4.2 방향 예고 배지 (이 게임의 최중요 UI)
- 각 레인 끝에 "N ×24" 형식, 위협도 색 인코딩: 빨강=위험 / 노랑=보통 / 회색=없음
- 배지 안에 해당 방향 **지배 속성 미니 아이콘** 병기 (§2.8) — 색 채널은 위협도 전용으로 유지하고 속성은 아이콘으로만 표현 (색 의미 충돌 금지)
- 절대 하단 패널에 묻지 말 것

### 4.3 하단 탭 5개
- **소환**: 벤치 슬롯(합성 가능 시 초록 테두리+"합성" 뱃지) + 소환 버튼(비용 표시, 우측 엄지 위치) + 등급 확률 노출
- **강화**: 키우기식 리스트 행 [아이콘 | 스탯명+Lv | 현재→다음 수치 | 골드 버튼]. 골드 부족 시 버튼 회색 비활성. 길게 누르면 연속 강화
- **스킬**: 같은 리스트 행 구조, 버튼이 "개방"으로 변경
- **장비**: 슬롯형 (유닛/소환사 선택 → 장착 슬롯)
- **소환사**: 같은 리스트 행 구조(소환사 스탯) + 메타 트리 입구
- 탭에 레드닷: 강화 가능/새 장비 획득 시
- 리스트 행은 UXML 템플릿 1개 + 데이터 바인딩으로 재사용 (강화/스킬/소환사 3탭 공용)
- 탭 열면 하단 패널 확장 + 필드 축소, 단 전투는 계속 보이게

### 4.4 소환사 스트립 (최하단 상시 노출)
- 초상화 + Lv + EXP바 + 강화 버튼. 어느 탭에서든 보임

### 4.5 기타 키우기 문법
- 소환 등급별 색 이펙트 (일반 회색 → 영웅 보라 → 전설 금)
- 재화 부족 시 버튼 회색 처리, 수치는 항상 "현재→다음" 변화량 표기

## 5. AI 에셋 파이프라인

### 5.1 3단 프롬프트 아키텍처 (기술 문서의 뼈대)

```
[레이어 1: 스타일 앵커 — 전 에셋 공통]
cute chibi fantasy game asset, big head small body, thick dark outline,
flat cel shading, solid green background (#00FF00), centered
(레퍼런스 톤: 모바일 키우기류 SD 캐릭터)

[레이어 2: 카테고리 변수]
유닛(고블린): + character sheet of the same goblin, 3 views in a row:
              front view, back view, side view facing right,
              idle pose, weapon visible
적(슬라임):   + single {slime_concept}, symmetrical blob shape, front view,
              desaturated pale gray body (엔진 틴트용)
UI 아이콘:    + single flat game icon of {concept}, simple shape

[레이어 3: 개체 변수]
{unit_concept} = "goblin archer with short bow" /
                 "goblin fire shaman with torch staff" / ...
{slime_concept} = "round slime" / "small speedy slime" / "big heavy slime" / ...
```

- 배경은 크로마키 그린으로 뽑아 제거
- **고블린은 3뷰 캐릭터 시트(정면/후면/측면) 1장 생성 → 슬라이스**: 남(정면)/북(후면)/동(측면)/서(측면 플립) 레인 대응. 4방향 개별 생성 대비 생성량 절약 + 캐릭터 내 일관성 확보
- 여러 유닛을 한 장에 그리드로 생성 후 잘라 쓰는 방식도 일관성에 유효

### 5.2 도구 분담
- 이미지: ChatGPT 이미지 생성 / 사운드 BGM: Suno / SFX: ElevenLabs 또는 jsfxr / 코드: Claude Code / 밸런스 테이블: LLM으로 CSV 생성

### 5.3 필요 에셋 목록 (생성 ~45장 이내)
- 고블린 유닛 8종 × 3뷰 시트 = **생성 8장** → 슬라이스 24컷 (등급 색변형은 틴트)
- 슬라임 형태 4종 × 1장 = 4장 (속성 변형은 틴트) + 보스 전용 2장
- 소환사(인간 주인공): 초상화(소환사 스트립용) 1장 + 전신 1장 (타이틀/로딩 일러스트 겸용)
- 코어(소환진) 피격 단계 2~3장, 타일/바닥 2~3장, 투사체·이펙트 4~6장
- UI 아이콘 ~20개 (**속성 아이콘 4종** — 무/화염/빙결/자연 — 포함)

### 5.4 기록 의무 (제출 요건 직결)
- **에셋 대장** 스프레드시트를 1일차부터 기록: 파일명 / 생성 도구 / 사용 프롬프트 / 라이선스·출처 → [docs/asset-ledger.csv](asset-ledger.csv)
- 프롬프트 실패→개선 사례(v1→v2→v3)를 겪을 때마다 스크린샷으로 보존 → `docs/prompt-cases/`
- 커밋 메시지에 AI 활용 흔적 남기기 (예: `feat: AI-generated unit sprites integrated`)

## 7. 제출물 체크리스트 (5종, 하나라도 누락 시 탈락)

1. **플레이 빌드 + 소스** — WebGL을 GitHub Pages로, 소스 전체 동일 저장소, 커밋 기록 유지, public 권장 (비공개 시 심사 계정 dl_gameai_reviewer@nhn.com 초대). 유료 라이선스 없이 실행 가능해야 함
2. **플레이 영상** — YouTube 30~60초, 실제 플레이 화면만(AI 합성·조작 불가). 컷 구성안: 타이틀 3s → 배치+전투 20s → 예고 보고 재배치 15s → 합성/성장 10s → 보스 10s
