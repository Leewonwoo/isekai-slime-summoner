## 1. 게임 컨셉

- **장르**: 자유 배치 소환 디펜스 × 로그라이크(메타 진행형) × 키우기
- **테마 (2026-07-15 개정)**: 중앙의 인간 **소환사**가 **슬라임 소환수**를 불러, 뷰포트 밖 여러 범위에서 몰려오는 **고블린 군단**을 막는다.
- **한 줄 요약**: 룰렛으로 슬라임을 소환하고 자유롭게 배치·2머지해, 움직이며 싸우는 소환수와 중앙 소환사의 원거리 공격으로 고블린 웨이브를 처치하는 디펜스
- **1런 길이**: 웨이브 수와 종료 시점은 고정하지 않고 `StageTimeline`의 목록과 이벤트로 결정한다.
- **핵심 딜레마**: 한정된 계약서로 어떤 소환수를 얻고 어디에 배치·재배치·머지할지, 소환사 레벨업 때 어떤 투사체 빌드를 쌓을지, 영구 특성과 5웨이브 대형 진화 중 무엇을 고를지 판단한다.

## 2. 핵심 시스템

### 2.1 필드
- 4방향 레인과 고정 슬롯은 사용하지 않는다. 중앙에 **소환사(주인공)가 고정**되고 나머지 필드 전체를 자유 배치 공간으로 사용한다.
- **코어 = 소환사 본인 (2026-07-11 개정, 소환석 구조물 폐기)**: 지켜야 할 대상이 구조물이 아니라 소환사 자신. "코어 HP" = 소환사 HP (코드 식별자는 기존 core 유지 가능 — 일괄 리네임 금지)
- **런 흐름**: 런 시작 → 소환사 중앙 등장 → 룰렛 소환 → 버튼 자동 배치 또는 벤치 카드 드래그 배치 → 웨이브 전투
- **소환수 자유 이동**: 배치된 슬라임은 기본 탐색 반경 4.5 월드 유닛 안의 타겟만 탐색해 이동·공격하고, 실제 타격 사거리는 `SummonUnitData.attackRange`를 따른다. 필드 경계를 벗어나지 않으며 서로의 겹침을 완화한다. 플레이어는 필드 슬라임을 누른 뒤 22px 이상 움직여 드래그로 전환하고, 처음 집은 지점의 오프셋을 유지한 채 필드 안의 유효한 빈 위치에 재배치할 수 있다. 드래그 중에는 유닛을 전면에 표시하고 유효·무효·머지 대상을 아웃라인으로 구분한다. 필드 밖이나 겹치는 무효 위치에 놓거나 앱 포커스가 끊기면 원래 위치로 복귀한다. 전투 중 배치가 끝나면 해당 슬라임은 새 위치에서 전투 AI를 재개한다.
- **전투 위치 보정(PBD)**: 소환수와 고블린은 각자 AI 이동을 마친 뒤 Position-Based Dynamics 접촉 제약으로 겹침을 보정한다. 팀별 간격·반복 횟수·보정 강도·inverse mass는 직렬화 설정으로 조정하며, 큰 개체와 높은 성급은 더 무겁게 취급한다. 얕은 겹침은 허용 오차로 무시하고, 보정 결과는 각 개체가 이번 프레임에 스스로 이동한 거리 안으로 제한한다. 정지한 개체는 다른 개체가 접근해도 PBD로 밀리지 않으며 접근한 개체의 이동만 멈추거나 꺾인다. 적대 개체 간 보정 거리는 실제 근접 공격 가능 거리를 넘지 않아야 하고, 드래그 중인 소환수는 PBD 대상에서 제외한다. PBD는 위치에만 관여하며 피해·공속·상성·웨이브 수치를 바꾸지 않는다. 세부 튜닝 기준은 [combat-dynamics-pbd.md](combat-dynamics-pbd.md)를 따른다.
- **전투 후 복귀 포메이션**: 웨이브 전투가 끝나 `Intermission`·`Prepare`·특성/상점·`Victory` 상태가 되면 살아 있는 슬라임은 소환사 주변의 동심원 슬롯으로 복귀한다. 지원·원거리·범위·근접 순으로 안쪽에서 바깥쪽에 배치하고 같은 역할은 인스턴스 ID로 위치를 고정한다. 복귀 중에도 PBD로 겹침을 완화한다. 준비 구간에 플레이어가 벤치 또는 필드 유닛을 드래그하면 자동 복귀를 즉시 취소하고, 다음 비전투 상태 전환 전까지 수동 배치를 우선한다.
- 적은 인게임 배경 `SpriteRenderer.bounds` 바깥 0.4~1.1 월드 유닛의 외곽 밴드에서 생성된다. 살아 있는 슬라임이 있으면 가장 가까운 슬라임을 우선 추적해 근접 공격하고, 필드의 슬라임이 모두 쓰러진 뒤에만 중앙 소환사에게 이동한다. 소환사에게 닿아 즉시 피해를 주고 사라지는 방식은 사용하지 않으며, 동일한 공격력·공속·사거리로 소환사를 반복 공격하다가 처치될 때만 풀로 돌아간다. 카메라 전체 뷰포트와 하단 UI 영역은 스폰 경계 계산에 사용하지 않으며, 배경 참조와 외곽 최소·최대 거리는 `GameManager`에서 조절한다.
- 소환사는 중앙에서 움직이지 않지만 기본 반경 4.5 월드 유닛 안의 가장 가까운 적을 자동 원거리 공격한다. 필드를 클릭하면 해당 적 또는 클릭 방향으로 별도의 쿨다운 공격을 발사하며, 클릭한 적이 사거리 밖이면 그 방향으로 최대 사거리까지만 발사한다.
- 버프 슬라임의 오러는 반경 안 아군 공격속도를 높이고 2초마다 손상된 다른 슬라임 1명을 회복한다. 회복량은 대상 최대 HP의 ★1 3% / ★2 4% / ★3 5%이며 시전자는 자신을 회복하지 않지만 다른 버프 슬라임은 대상으로 삼을 수 있다. 같은 대상에 여러 오라가 겹치면 공격속도와 회복 모두 가장 강한 오라 하나만 적용하고, ★3 `과충전 공명` 중에는 해당 오라의 공격속도 보너스와 회복량을 2배로 증폭한다. 실제 버프 또는 회복 적용 순간에만 반투명 초록 펄스가 퍼졌다 사라지며, 회복량은 초록 `+N` 플로팅 텍스트로 표시한다. 최대 크기는 `SummonUnitData.supportRadius`와 같은 월드 반지름이고 성급별 본체 크기와 무관하게 범위를 유지하며, 짧은 재생 간격으로 과도한 중첩을 제한하고 풀 반환 시 즉시 숨긴다.
- 소환사 HP 0 = 런 종료(패배)
- 소환사·고블린·필드에 배치된 슬라임은 월드 `SpriteRenderer` 체력바를 머리 위에 표시한다. 바는 캐릭터 스프라이트 바운드에 맞춰 폭·위치를 보정하고, 등급/크기 스케일과 무관하게 두께를 유지한다. 소환사 바는 금색, 슬라임은 초록, 고블린은 빨강으로 구분한다.
- 실제로 차감된 피해량은 액터 위치를 화면 좌표로 투영한 uGUI 플로팅 숫자로 표시한다. 액터마다 Canvas를 만들지 않고 Screen Space Overlay 전용 Canvas 하나에서 `Text`를 24개 선생성·최대 64개까지 풀링하며, 같은 폰트·머티리얼과 입력 비활성 설정으로 배칭한다. 숫자 이동으로 인한 Canvas 리빌드는 이 전용 Canvas 안에만 격리하고, 서비스 하나의 `LateUpdate`에서 0.72초 동안 일괄 상승·페이드한다. 적이 받은 피해는 웜 화이트, 슬라임·소환사가 받은 피해는 빨강으로 구분하며 게임플레이 일시정지 중에는 함께 멈춘다.
- 슬라임 기본 최대 HP는 `SummonUnitData.baseMaxHp`와 등급별 HP 배율로 정의한다. 고블린의 반복 근접 공격으로 HP가 0이 되면 해당 슬라임은 필드에서 제거되고, 공격하던 고블린은 다음 슬라임 또는 소환사로 목표를 전환한다.

### 2.2 소환·머지 (핵심 경제 루프 — 2026-07-14 계약서 경제로 개정)
- **소환 = 운빨**: 런 전용 재화 **용병 계약서 1장** 소모 → 해금된 슬라임 풀에서 **종류 랜덤** 획득. 기본 **★1 유닛**으로 등장
  - 골드는 몬스터 처치로 획득해 인게임 강화에만 사용하고, 소환 비용과 분리한다.
  - 계약서는 런 시작 시 **4장**, 일반 웨이브 클리어 시 **1장**, 5웨이브 단위 클리어 시 **2장**을 지급한다. 최종 웨이브는 0장이다. 정확한 수치는 웨이브 SO/밸런싱 CSV에서 조정한다.
  - 마지막 웨이브는 이후 소환 구간이 없으므로 계약서 대신 승리·보스 보상을 지급한다.
  - 낮은 확률(초기 ~5%)로 **★2 직행 잭팟** — 소환사 레벨/메타의 "소환 확률 개선" 스탯은 이 직행 확률을 올리는 것으로 재정의
  - 연출: **슬롯머신 릴** (소환 탭 내). 3릴이 같은 유닛으로 정렬되면 ★2 직행 — 잭팟 확률을 슬롯 문법으로 시각화. 단 **로직 먼저, 릴 연출은 폴리싱 단계(3주차 이후)** — v1은 결과 즉시 표시 + 탭 스킵 가능해야 함 (소환을 수십 번 누르는 게임이므로 연출이 템포를 막으면 안 됨). 단일 가로 릴 프로토타입은 카드 사이를 붙여 연속 띠처럼 보이게 하고, 확정 결과 앞뒤에도 미끼 카드를 유지한 채 중앙 선택선에서 정지해야 한다. 결과 카드를 배열 마지막에 두지 않는다.
- **머지 (필드 드래그 2합성)**: 같은 종류 + 같은 성급 2개 = 다음 성급 유닛 1개. 필드 유닛을 같은 종류·성급 대상 위에 드롭하면 드래그한 재료를 소비하고 대상이 즉시 승급한다. **★1 → ★2 → ★3 (최대)**
  - ★3 1개 = ★1 4개 환산 — 한 런에서 ★3이 지나치게 범람하지 않도록 계약서 수급과 소환 확률을 밸런싱 CSV에서 조정한다.
  - 벤치/필드를 합쳐 같은 종류·성급 유닛이 2개 이상이면 합성 가능 상태로 표시하며, 실제 합성은 필드의 두 유닛을 겹쳐 드롭한다. 드래그 중 Animated Sprite Outline으로 유효·무효·머지 대상을 구분한다.
- 보유 한도는 벤치와 필드에 살아 있는 슬라임을 합친 **총 개체 수**로 센다. 기본 8칸, 최대 12칸이며 같은 유닛 + 같은 머지 등급은 UI에서 한 슬롯에 스택하고 `xN` 수량으로 표시한다. 한도에 도달하면 계약서를 소비하지 않고 소환 버튼을 비활성화한다. 벤치→필드 드래그 시 해당 스택에서 1개를 꺼내 배치하고 필드 자유 재배치를 지원한다.
- 슬롯은 골드 저장 강화 `슬라임 슬롯`(+1, 최대 4회) 또는 소환사 레벨업 영구 특성 `지휘 확장`(+1, 최대 4레벨)으로 늘린다. 두 보너스는 합산하되 현재 보유 한도는 12칸을 넘지 않는다. 영구 특성은 다음 런의 시작 슬롯을 늘려 슬롯 강화 골드를 절약하는 가치가 있다.
- 룰렛에서 슬라임 결과가 확정되면 소환사 주변의 유효한 빈자리를 찾아 즉시 자동 배치한다. 필드에 배치 가능한 위치가 없을 때만 해당 유닛을 벤치 스택에 유지하며, 이 경우 기존 드래그 배치를 사용한다.
- 유닛 강화 레벨과 강화로 얻은 공격력/공속 배율은 `unitId`별 공유 상태로 관리한다. 따라서 같은 슬라임의 모든 머지 등급·벤치 개체·필드 개체에 동시에 적용하되, 머지 등급은 기존처럼 개별 인스턴스 상태로 유지한다.
- 유닛 판매 가능 (소량의 골드 지급 — 벤치가 막힐 때의 배출구). 계약서는 환급하지 않아 판매→재소환 리롤 반복을 막는다.
- ⚠️ 해금 유닛이 늘수록 소환 풀 희석으로 머지 난도가 오름 — v1은 전체 풀 균등 랜덤으로 가고, 플레이테스트에서 희석이 체감될 때만 "런 시작 시 출전 덱 4~6종 선택"을 검토 (문제 확인 전에 미리 넣지 말 것)

### 2.4 성장 축 4개
1. **저장 강화 (골드, PlayerPrefs 저장)**:
   - 전체 공격력/전체 공격속도/소환사 HP 즉시 회복/치명타를 키우기식 리스트에서 강화한다.
   - 보유한 슬라임은 `unitId`별 공통 레벨을 골드로 즉시 올린다. 같은 종류의 모든 머지 등급·벤치·필드 개체에 공격력/공속 배율이 즉시 반영되며 다음 런에는 유지되지 않는다.
2. **소환사 레벨업 투사체 빌드 (선택 효과는 런 한정, 2026-07-25 개정)**:
   - 고블린 처치 EXP는 기존 **소환사 EXP** 한 곳에만 지급한다. 별도의 마력 EXP·전투 EXP·마력 레벨·전투 레벨은 사용하지 않는다.
   - 소환사 레벨이 실제로 1 오를 때마다 전투를 일시정지하고 `RunRewardCatalog`에서 현재 조건에 맞는 **투사체 빌드 3택**을 한 번 제시한다. 한 번에 여러 레벨이 오르면 오른 레벨 수만큼 선택권을 순서대로 처리한다.

   - 모바일 성능을 위해 소환사 기본탄·보조탄·자식탄의 동시 활성 상한은 48개로 둔다. 상한을 넘는 연쇄·반사 후속타는 새 GameObject를 만들지 않고 즉시 피해와 짧은 적중 이펙트로 대체하며, 모든 실제 투사체는 기존 풀을 사용한다.
3. **소환사 영구 레벨 (주인공, 2026-07-17 개정)**:
   - 고블린 처치로 얻는 소환사 EXP와 레벨은 JSON 직렬화 후 `PlayerPrefs`에 저장해 런을 넘어 유지한다.
   - EXP를 얻는 즉시 현재 레벨 요구량을 연속 차감해 가능한 만큼 자동 레벨업하며, 공격력·최대 HP·★2 직행(잭팟) 확률이 증가한다. 수동 레벨업 버튼은 사용하지 않는다.
   - 소환사 레벨 2회 상승마다 미선택 영구 특성 선택권 1개를 지급한다. 권리 수는 `floor((소환사 레벨 - 1) / 2)`이며, uGUI 3택 팝업은 비전(소환사 공격력/공격속도)·지휘(슬라임 공격력/공격속도/슬롯)·생존/수집(최대 HP/★2 직행 확률/장비 보급/신물 발견) 그룹에서 각각 1개를 제시한다. `장비 보급`은 미보유 장비 1개를 영구 획득하고, `신물 발견`은 획득 가능한 속성 신물을 ★1로 얻거나 보유 신물을 한 단계 승급한다. 모든 장비 또는 모든 신물 계열이 완성되면 해당 선택지는 자동 제외한다.
   - 슬롯 특성은 최대 4레벨, 나머지 특성은 최대 10레벨이다. 모든 경로를 합친 최종 ★2 직행 확률은 25%를 넘지 않는다.
   - 특성 저장은 소환사 레벨 저장과 분리한 JSON + `PlayerPrefs` 키를 사용한다. 기존 v1 저장의 누적 레벨은 삭제하거나 강등하지 않으며, 새 권리 수가 이미 선택한 총 레벨을 초과할 때만 이후 선택권을 지급한다.
   - 레벨업으로 최대 HP가 오르면 해당 증가분만 현재 HP에도 더한다. 저장 데이터가 없거나 손상되면 Lv.1/EXP 0의 안전한 기본값으로 시작한다.
   - 스킬 개방과 아이템 장착의 주체다.
   - **기본 공격 투사체 (2026-07-19 개정)**: 사거리 안의 가장 가까운 적을 자동 조준해 정적 스프라이트 투사체를 발사한다. 무속성 비전탄(기본값) / 화염구(화염·범위/연소) / 빙결창(빙결·관통/둔화) / 전격구(전기·연쇄) 4종을 각성 타입에 따라 교체한다. 투사체는 소환사 하위 `FirePosition`을 발사 원점으로 사용하고, 풀링한 뒤 진행 방향으로 회전한다. 비행 중 원래 대상이 죽거나 풀에서 다른 몬스터로 재사용되면 새 적을 재조준하지 않고 원래 대상의 마지막 위치까지 이동해 0.12초 무피해 소멸 폭발을 재생한다.
4. **메타 진행 (런 간 영구)**: 소환사 레벨·영구 특성·강화 탭 레벨·unitId별 슬라임 공통 강화 레벨·슬라임 해금·몬스터 도감·소환사 신물을 JSON + PlayerPrefs로 저장한다. 소환사 레벨업 때 고른 투사체 빌드는 저장하지 않는다. 슬라임은 주먹을 기본으로 하고 물총 Lv.2 / 불꽃 Lv.6 / 얼음 Lv.8 / 초록 Lv.12 / 버프 Lv.16 / 폭발 Lv.20 / 빙결 Lv.24에 자동 해금한다. 별도 젬 경제는 사용하지 않는다.
   - 플레이테스트 초기화는 Unity 메뉴 `Isekai Slime Summoner > Debug > 영구 진행 초기화`에서 수행한다. 소환사 레벨·영구 특성·소환사 버프 장착·몬스터 도감·신물 저장만 삭제하고, Play 중 실행하면 다음 씬 로드 시작점에서 삭제한 뒤 웨이브 1/Lv.1로 다시 시작한다.
   - Unity Device Simulator와 일반 Game 뷰를 함께 열어 테스트할 때는 포커스된 창에 맞춰 입력 장치를 전환한다. Simulator 포커스에서는 시뮬레이터 Touchscreen을 사용하고, Game 뷰 포커스에서는 Simulator 플러그인이 비활성화한 네이티브 Mouse를 에디터 브리지에서 복구한다. 런타임 빌드 입력에는 이 브리지를 포함하지 않는다.

### 2.5 스킬 / 신물
- **전투 스킬 구성**: 장착한 공격 신물의 액티브 스킬 1개와 소환사 버프 5종 중 장착한 3개를 함께 사용한다. 신물 스킬은 속성 공격을, 소환사 스킬은 생존·회복·군단 강화·신물 보조만 담당하며 소환사 버프가 직접 피해를 주지 않는다. 네 스킬은 독립 쿨다운을 사용하고 런 시작 시 즉시 사용 가능하다. 쿨다운과 지속 시간은 전투 일시정지·모달·웨이브 사이에 진행하지 않는다.
- **신물 스킬**: 속성 공격 액티브 스킬은 장착한 공격 신물 1개의 계열·성급에 귀속된다. 별도 스킬 강화 레벨은 두지 않으며, 신물 승급 시 스킬 이름·효과·아이콘이 함께 승급한다. 장착 신물 ID와 계열별 보유 성급을 영구 저장하고 피해에는 실제 소환사 공격력 배율을 적용한다.
- **소환사 버프**: 총 5종 중 최대 3개를 장착하고 장착 목록을 영구 저장한다. 해금·장착 변경은 스킬 탭에서 처리하며 장착을 해제해도 진행 중인 쿨다운은 초기화하지 않는다.

#### 2.5.1 콤보 / 오버드라이브 (도파민 루프, 2026-07-21 확정)

- **핵심 루프**: 고블린 연속 처치 → 콤보 상승 → 오버드라이브 게이지 가속 → `마력 폭주` 발동 → 메테오 샤워로 다음 처치 연쇄를 만든다. 별도 장착 슬롯이나 두 번째 액티브 스킬은 추가하지 않는다.
- **콤보 판정**: 소환사·슬라임의 기본 공격/★3 스킬/액티브 스킬/지속 피해로 고블린이 죽으면 적 1기당 콤보가 1 오른다. 같은 프레임의 광역 처치도 각 적을 따로 센다. 도주·강제 디스폰은 세지 않는다.
- 마지막 유효 처치 후 **2.0초** 안에 다음 처치가 발생하면 콤보를 이어가고 제한 시간을 갱신한다. 제한 시간은 전투 일시정지·모달 중에는 줄지 않으며, 웨이브 클리어 시 콤보만 0으로 초기화한다.
- 콤보는 피해·드랍·EXP를 직접 배율 증가시키지 않고 오버드라이브 충전량만 바꾼다. 밸런스와 플로팅 숫자 가독성을 위해 화면에는 `xN COMBO` 하나만 표시하며, 10/20/30 연쇄 진입 때 한 번씩 크기·색·사운드를 강조한다.

| 현재 콤보 | 처치당 게이지 |
|---:|---:|
| 1~9 | +3 |
| 10~19 | +5 |
| 20~29 | +8 |
| 30+ | +12 |

- 콤보가 2초 유예시간 만료로 끊기면 **콤보 정산**을 발동한다. 살아 있는 모든 적에게 `실제 소환사 공격력 × 종료 콤보 수 × 0.1`의 무속성 피해를 동시에 주고 `종료 콤보 수 × 1` 골드를 즉시 지급한다. 최소 2콤보부터 정산하며 웨이브 종료·승패·강제 초기화로 콤보를 지울 때는 발동하지 않는다. 정산 피해로 발생한 처치는 새로운 콤보와 오버드라이브 게이지에 정상 반영한다.
- **오버드라이브 게이지**는 0~100이며 웨이브 사이에도 유지되고 감쇠하지 않는다. 100이 되었을 때 살아 있는 적이 있으면 자동 발동하고, 적이 없으면 `READY` 상태로 다음 전투까지 보존한다. 패배·승리·스테이지 재시작 때만 0으로 초기화한다.
- **마력 폭주**는 장착 신물 빌드를 강화하는 소환사의 공용 오버드라이브다. 게임플레이 시간 **6.0초** 동안 소환사 공격력 **×1.3**, 공격속도 **×1.5**를 적용한다. 슬라임 능력치는 변경하지 않는다.
- 발동 순간 장착 신물 스킬의 쿨다운을 먼저 0으로 초기화한 뒤 살아 있는 적 하나를 자동 조준해 해당 신물 스킬을 즉시 1회 발사한다. ★2는 지정 구역 4회 집중 공격, ★3은 전장 전체 12회 연속 공격 규칙을 그대로 사용하며 별도의 폭류유성이나 소형 메테오를 생성하지 않는다.
- 자동 발사 직후에는 해당 신물의 정상 쿨다운이 다시 시작된다. 오버드라이브 지속 중 추가 초기화는 없으며 플레이어는 쿨다운이 돌아오면 신물 스킬을 다시 직접 사용할 수 있다.
- 지속 시간은 살아 있는 적이 있고 게임플레이가 진행될 때만 흐른다. 활성 중에는 게이지를 다시 얻지 않으며 종료 뒤 0부터 충전한다. 수치는 `DopamineBalanceData`의 지속 시간·공격력 배율·공격속도 배율로 조정한다.

- **영구 장비**: 소환사 전용 무기·방어구·장신구 각 1슬롯. 고정 옵션 장비를 행상인에게 골드로 구매하고 보유/장착 ID를 영구 저장한다. 랜덤 옵션·분해는 넣지 않는다.
  - 초기 장비는 공격력 무기 3종, 최대 HP 방어구 3종, 공격속도·치명타·★2 직행 확률 장신구 각 1종의 총 9종이다. 빈 슬롯의 첫 구매품만 자동 장착하며 이후 구매품은 가방에 보관한다.
  - 보유/장착 상태는 `CrossDefense.Equipment.v1` PlayerPrefs JSON으로 저장하며, 존재하지 않거나 슬롯이 맞지 않는 ID만 무시한다.
- **전리품**: 행상인이 판매하는 슬롯 없는 스테이지 한정 패시브다. 같은 전리품은 스테이지당 1회만 구매한다. 앱 종료·패배·같은 스테이지 재시작·웨이브/DAY 전환에는 유지하고, `StageTimeline.StageId`가 다른 다음 스테이지로 넘어갈 때만 제거한다. 내부 `RunRelic*` 타입은 저장 호환을 위해 유지한다.
  - 초기 효과는 전체 공격력, 전체 공격속도, 처치 골드, 소환사 최대 HP, 웨이브 계약서, ★2 직행 확률의 6종이다.

### 2.6 웨이브 설계 (규칙 기반 — 런타임 API 호출 없음)
- 웨이브 수는 코드에 고정하지 않고 `StageTimeline.waves.Count`로 결정한다. 현재 `Stage_01`은 **50웨이브**로 구성하며 각 웨이브는 적 조합·물량·HP/속도/보상 계수·스폰 간격을 가진다.
- **5웨이브마다 보스 웨이브**를 배치한다. 보스는 별도 이미지·별도 `MonsterData`를 만들지 않고 해당 웨이브에 등장 가능한 일반 고블린 중 1종을 선택해 스폰 항목의 HP·보상·속도·크기 배율을 덧씌운다. 모든 일반 스폰 항목은 가독성을 위해 크기 배율 **×1.5**, 보스 스폰 항목은 **×3.0**을 사용한다. 같은 종류가 이후 일반병으로 나오면 다시 일반 배율 ×1.5를 적용한다.
- 원거리 고블린은 `MonsterData.attackStyle=Projectile`과 개별 사거리·공격속도·투사체 속도/크기를 사용한다. 사거리 안에서 이동을 멈추고 슬라임을 우선 조준하며, 슬라임이 없을 때 소환사를 공격한다. 투석병·화염 폭탄병/술사·빙결 궁수/주술사·포자 주술사·가시 사냥꾼을 원거리 타입으로 운용한다.
- Top/Right/Bottom/Left는 레인이 아니라 **뷰포트 밖 스폰 구역 가중치**다. 선택된 구역 안에서도 위치와 바깥 여백을 변주한다.
- 난이도 곡선(적 HP/수량)은 지수 성장 기반, 테이블 수치는 LLM으로 CSV 생성 후 SO로 임포트 — **개발 도구로서의 AI 활용 사례로 기술 문서에 기록**
- 런마다 약간의 변주를 주되 동일 시드에서는 같은 스폰 순서를 재현한다.
- **러쉬 웨이브**는 `StageWaveKind.Rush`로 표시하고 8·18·28·38·48웨이브에 배치한다. 여러 스폰 항목을 병렬로 빠르게 생성하되 살아 있는 적은 최대 64기로 제한한다. 전멸 시 추가 골드 40/70/100/130/160을 한 번 지급하고 곧바로 행상인을 연다.
- 특성/보상 3택은 세 계층으로 분리한다. 소환사 레벨 2회마다 얻는 영구 특성은 런을 넘어 누적되고, 소환사 레벨이 오를 때마다 투사체 수·공속·관통·분열·반사 같은 런 한정 소형 빌드를 하나 고르며, 기본 5웨이브 대형 진화는 속성 주 공격·공격 진화·슬라임 군단·즉시 소환을 구성한다. 투사체 빌드와 대형 진화는 해당 도전에서만 유지된다. 황금 고블린·행상인은 타임라인 이벤트 데이터로 등장 조건을 정한다.
- 행상인은 러쉬 클리어 보너스를 지급한 뒤 `Merchant` 상태에서 연다. 상품은 장비 1개·소모품 1개·전리품 1개이며, 구매 없이 닫을 수 있다. 구매 불가 상품은 숨기지 않고 비활성화한다.
  - 소모품은 소환사 최대 HP의 35% 회복, 계약서 2장, 해금된 무작위 ★1 슬라임 즉시 지급 3종만 사용한다. 처리 순서는 `러쉬 전멸 → 계약서 보상 → 러쉬 골드 보너스 → 행상인 → Intermission → 다음 Prepare`로 고정한다.
- 소환사 영구 특성·소환사 레벨업 빌드·대형 진화 3택 팝업과 소환 룰렛 모달이 표시되는 동안 웨이브 타이머·스폰·몬스터·슬라임·소환사 공격·투사체·드랍 재화 이동·필드 입력을 정지한다. 팝업 입력과 룰렛 연출은 비스케일 시간으로 계속 진행하며, 여러 모달 정지 사유가 겹치면 마지막 모달이 닫힌 뒤에만 게임플레이를 재개한다.
- 소환사 사망 시 현재 스테이지의 DAY 1부터 다시 시작하며 보유 슬라임도 초기화한다. 앱 재실행 시에는 마지막으로 진입한 DAY 번호, 소환사 HP 비율, 생존 중이던 보유 슬라임의 종류·성급·수량·개체별 HP 비율을 복구해 해당 DAY의 시작부터 소환사 주변에 자동 배치한다. 체력 체크포인트는 1초마다 갱신하고 앱 백그라운드 전환·정상 종료 시 즉시 저장한다. 이미 사망한 슬라임은 복구하지 않으며 저장된 소환사 HP가 0이면 정상 패배와 동일하게 DAY 1 및 보유 슬라임 초기화를 적용한다. 슬라임 위치, 계약서, 투사체 빌드·콤보는 초기화하고, 오버드라이브는 `StageTimeline.startingOverdriveGauge`에서 시작한다. 보스 웨이브 클리어로 획득한 대형 진화 특성과 행상인 전리품은 앱 종료·사망·같은 스테이지 재시작·웨이브/DAY 전환에도 유지하며, `StageTimeline.StageId`가 다른 다음 스테이지로 넘어갈 때만 초기화한다. DAY 내부의 생존 몬스터·처치 수·스폰 진행도는 복구하지 않는다. 골드는 `CrossDefense.Wallet.v1` 영구 지갑에서 복원하며, 소환사 레벨·EXP·영구 특성·강화 탭 레벨·unitId별 슬라임 공통 강화 레벨·장비·신물도 `PlayerPrefs`에서 복원한다.

### 2.7 적 — 고블린 군단

- 기본 고블린은 `MonsterData`의 HP·속도·공격력(`contactDamage`)·초당 공격 횟수·공격 사거리·골드 보상·속성·크기 데이터로 구성한다. 타겟 탐색은 매 프레임이 아닌 0.2초 간격으로 갱신한다.
- 속성은 상성 계산에만 사용하고 `SpriteRenderer.color` 틴트를 적용하지 않는다. 화염·빙결·자연을 포함한 모든 고블린은 생성된 원본 스프라이트 색상을 그대로 표시한다.
- 정면 기본 스프라이트 로스터는 50웨이브의 속성·역할 조합을 위해 16종으로 구성한다. 일반병·화염 정찰병·빙결 중갑병·자연 약탈자·족장·화염 대전사·원거리 투석병·황금 고블린·화염술사·화약 폭탄병·서리 추적자·빙결 궁수·얼음 주술사·가시 사냥꾼·나무껍질 방패병·포자 주술사를 모두 개별 `MonsterData`와 `Stage_01`에 연결한다.
- `enemy_goblin_grunt`만 이동 중 9 FPS run 시트를 반복 재생하고 실제 공격 판정 때 18 FPS attack 시트를 1회 재생한다. 나머지 15종은 전용 애니메이션 제작 전까지 각자의 정면 기본 이미지를 이동·공격 중에도 유지하고 코드 흔들림·스쿼시 연출을 사용한다. 프레임 배열과 FPS는 `MonsterData`에서 몬스터 종류별로 교체 가능하다.
- 고속·탱커·원거리형 등 기획된 몬스터는 같은 생명주기 위에 데이터와 행동 훅으로 확장한다.
- **황금 고블린**은 낮은 확률 또는 지정 웨이브 이벤트로 등장하고 일반 적과 구분되는 외형·보상·도주 규칙을 가진다.
- **몬스터 도감**은 16종 고블린을 고정 순서로 나열한다. 첫 스폰 때 영구 조우 처리하고 실제 처치만 누적한다. 미조우 슬롯은 `?`, 조우 슬롯은 이미지·이름·속성을 표시하며 상세에서 기본 전투 수치와 누적 처치 수를 보여준다.
  - 도감 진행은 `CrossDefense.MonsterCodex.v1` PlayerPrefs JSON으로 저장한다. 전체화면 4×4 도감이 열리면 `GameplayPauseReason.MonsterCodex`로 전투와 필드 입력을 정지하고 닫기 또는 Android 뒤로가기로 해제한다.
- **슬라임 도감**은 소환 풀 8종을 고정 순서로 나열하고 소환사 레벨에서 해금 상태를 실시간 파생한다. 잠긴 슬롯은 `?`와 해금 레벨만, 해금 슬롯은 ★1 이미지·이름을 표시하며 상세에서 속성·희귀도·공격 방식, ★1 기본 전투 수치와 ★3 스킬을 보여준다. 별도 발견·처치 저장은 추가하지 않는다.
  - FieldOverlay 우상단에는 `슬라임 도감` 버튼을 `몬스터 도감` 버튼 위에 배치한다. 전체화면 슬라임 도감이 열리면 `GameplayPauseReason.SlimeCodex`로 전투와 필드 입력을 정지하고 닫기 또는 Android 뒤로가기로 해제한다.
- FieldOverlay 우상단 설정 버튼 아래의 배속 버튼으로 게임플레이를 `×1.0 / ×1.5` 전환한다. 선택값은 영구 저장하며 모달이 열리면 배속과 무관하게 0으로 정지하고 닫히면 선택 배속을 복원한다.
- 적이 죽으면 PoolBoss 골드 오브가 처치 위치에서 TopHUD 골드 앵커로 흡수되고, 도착 시 재화와 숫자 카운트업을 확정한다.

### 2.8 속성 상성 (양방향)

- 속성 7종: **무 / 화염 / 빙결 / 자연 / 전기 / 물 / 바람**. 기존 에셋 직렬화 호환을 위해 무=0, 화염=1, 빙결=2, 자연=3의 enum 값은 유지하고 신규 속성을 뒤에 추가한다.
- 배율은 약점 공격 **×1.5**, 방어 속성이 우세한 공격은 **×0.65**, 동일 속성은 **×0.75**, 중립과 무속성은 **×1.0**이다. 직접 피해와 지속 피해에 같은 배율을 적용한다.
- 강속성 표는 공격→방어 기준으로 `화염→자연`, `자연→빙결·물`, `빙결→화염·바람`, `물→화염`, `전기→물·빙결`, `바람→전기·자연`이다. 표의 역방향 공격은 반감된다.
- 상성은 슬라임·소환사·신물 공격이 고블린에게 들어갈 때뿐 아니라 속성 고블린의 근접·원거리 공격이 속성 슬라임에게 들어올 때도 적용한다. 무속성 소환사 코어 피해는 기존 수치를 유지한다.
- 전격구·낙뢰/뇌운폭격/류진낙하는 전기, 수압탄/폭포낙하/창해폭류는 물, 돌풍/용오름/천공폭풍은 바람 속성을 사용한다.
- `ElementalMatchup`이 강속성 표와 배율의 단일 계산 경로이며, UI와 데이터는 `MonsterAttribute`를 공유한다.

## 3. 플랫폼·기술 스택

- **엔진**: Unity (2D, URP 불필요 시 Built-in)
- **빌드 타깃**: Android APK, IL2CPP + ARM64, 제품명 `isekaislimesummoner`, 패키지 `com.nenestudio.isekaislimesummoner`
- **화면**: 세로 1080×1920 고정(Portrait). 접수 요강의 기존 브라우저 플레이 요구와 APK 허용 여부는 제출 전 별도 확인한다.
- **UI**: UI Toolkit (UXML/USS) — HUD·하단 패널·배지 전담
  - PanelSettings: Reference Resolution 1080×1920, Scale With Screen Size, Match Width(0)
  - 유닛/몹/투사체/필드는 월드 오브젝트(SpriteRenderer) — UI Toolkit으로 필드를 그리지 말 것
  - 월드 앵커 UI(방향 배지 등)는 WorldToScreenPoint → 패널 좌표 변환으로 동기화
  - 드래그 앤 드롭(벤치 UI → 필드 월드): PointerDownEvent → 이동 임계값 → 월드 프리뷰 → PointerUpEvent에서 필드 경계와 겹침 검사 → 자유 좌표 배치 또는 벤치 복귀
- **연출**: 정적 스프라이트 + DOTween 코드 연출을 기본으로 한다. 단, 적 `enemy_goblin_grunt`의 정면 달리기·몽둥이 공격과 중앙 소환사의 idle·기본 지팡이 공격은 각각 3×3 9프레임 시트를 허용한다. 액티브 스킬 VFX는 핵심 연출 2종(`effect_fire_explosion_sheet`, `effect_ice_wall_sheet`), ★3 유닛 스킬 VFX는 폭발 슬라임 전용 `effect_explosion_slime_star3_eruption_sheet` 1종, 적 사망 VFX는 전 고블린 공용 `effect_goblin_death_sheet` 1종에 한해 3×3 9프레임 비반복 시트를 허용하며, 셀당 128×128px·18 FPS를 사용한다. 화염 폭발·고블린 사망은 공통 중심 피벗, 얼음벽은 공통 하단 중앙 지면 앵커, 폭발 슬라임 분화는 공통 하단 중앙 머리 앵커를 고정한다. 고블린 사망 시트에는 특정 체형·무기·속성 실루엣을 넣지 않고 녹갈색 마력 파편만 사용해 전 종에 재사용한다. 모든 캐릭터 애니메이션 시트의 정렬·루트 앵커·고정 셀·피벗은 [공통 마스터 프롬프트](prompts/animation-master-prompt.md)를 따른다. Animated Sprite Outline은 선택·배치 유효성·머지 대상 피드백에 사용한다.
- **아키텍처**: 웨이브/유닛/강화 데이터는 ScriptableObject, 몬스터·소환수·투사체·골드 드랍은 PoolBoss로 풀링한다.
- **월드 체력바 최적화**: 액터별 Canvas/UIDocument를 만들지 않는다. 풀링 액터의 자식 `SpriteRenderer` 2개(배경/채움)가 런타임 1px 스프라이트를 공유하며, 매 프레임이 아니라 HP·등급·스프라이트 크기가 변할 때만 채움과 배치를 갱신한다. 화면 밖 렌더링은 Unity 카메라 컬링에 맡긴다.
- **데미지 플로팅 텍스트 최적화**: 정적 UI와 분리된 uGUI Overlay Canvas 하나만 런타임 생성한다. 입력·마스크·레이아웃을 끄고 내장 폰트/머티리얼을 공유한 `Text` 풀을 사용하며, 활성 숫자는 서비스 한 곳에서 일괄 갱신한다. 선생성 24개·최대 64개 상한으로 폭발적인 생성과 오버드로우를 제한한다.

### 4.2 웨이브 상태 표시
- 방향 예고 배지(N/E/S/W)는 사용하지 않는다.
- HUD 아래 필드 상단 중앙에 현재 웨이브("WAVE 12")와 해당 웨이브 잔여 몬스터 수를 함께 표시한다.
- 콤보는 웨이브 상태 바로 아래에 `xN COMBO`로 표시하고 2콤보부터 노출한다. 제한 시간 만료·웨이브 클리어 때 숨긴다.
- 별도의 마력·전투 레벨 HUD는 두지 않는다. TopHUD와 소환사 탭의 `Lv.N` 및 EXP 바가 유일한 소환사 레벨 진행 표시이며, 레벨업 순간 투사체 빌드 3택을 연다.
- 오버드라이브 게이지는 우하단 스킬 버튼 왼쪽에 같은 바닥선으로 세운 연료 탱크 형태로 배치한다. fill은 아래에서 위로 차고 25% 구획선을 표시하며, 충전 중에는 수치 없이 fill만, 충전 완료는 게이지 위에 `READY`, 활성 중에는 `OVERDRIVE`와 남은 시간을 표시한다.
- 웨이브 방향 가중치와 실제 적 스폰은 런타임 게임 로직에서 처리하며, 상단 HUD는 표시 전용이다.

### 4.3 하단 탭 5개
- **소환**: 벤치 대기 유닛과 필드에 자동/수동 배치된 유닛을 합친 **전체 보유 유닛**을 최대 12슬롯 **3열 × N 세로 스크롤 그리드**로 표시한다. 현재 해금되지 않은 슬롯은 숨긴다. 같은 유닛 + 같은 머지 등급은 슬롯 하나로 묶고 `xN` 전체 수량과 유닛 공통 강화 레벨을 표시한다. 각 대형 슬롯의 이미지는 현재 성급의 `WorldSpriteAtRank`를 사용하고 아이콘·이름·현재 머지 등급을 넣으며, 탭하면 현재 성급 이미지와 공통 강화 기준 전투 수치, 같은 unitId 전체에 적용되는 슬라임 레벨업 버튼이 있는 상세 팝업을 연다. 드래그 배치는 해당 스택에 벤치 대기 개체가 있을 때만 1개를 꺼내 시작하며, 필드 배치 개체만 있는 슬롯은 상세 열람만 가능하다. 수량이 2개 이상이고 ★3 미만이면 초록 테두리+"합성" 뱃지를 표시한다. `보유 m/n · 슬롯 s개` + 용병 계약서 보유량 + `소환 ×1` 버튼(우측 엄지 위치) + ★2 직행 확률 노출. 전체 8종을 선택 슬롯처럼 상시 나열하지 않는다(선택 소환 오인 방지). 슬롯머신 릴 연출은 폴리싱 단계에 추가 (§2.2)
  - 합성 뱃지/프리뷰에 **다음 성급 진화 이름** 노출 (예: "기사 → 장군") — 진화 서사를 파는 지점 (§2.3)
- **강화**: 저장되는 전체 공격력·전체 공격속도·회복·치명타 강화만 모은 성장 허브. 키우기식 리스트 행 [아이콘 | 스탯명+Lv | 현재→다음 수치 | 골드 버튼]을 사용한다. 소환사 레벨업은 EXP 획득 시 자동 처리하고 unitId별 슬라임 레벨업은 슬라임 상세 팝업에서 처리한다. 골드가 부족하면 버튼을 회색 비활성화하며 길게 누르면 연속 강화한다.
- **스킬**: 같은 리스트 행 구조, 버튼이 "개방"으로 변경
- **가방**: `장비 / 신물 / 전리품` 내부 탭. 장비 슬롯과 보유 목록, 장착 신물과 고유 공격, 현재 도전의 전리품과 5웨이브 특성을 각각 표시
- **소환사**: 버튼형 강화 행 없이 상단 프로필(초상화·이름·Lv·EXP)과 실제 적용 중인 공격력·공격속도·최대 HP·치명타·★2 직행 확률을 표시한다. 현재 도전의 투사체 빌드와 중첩 레벨, 5웨이브 대형 진화는 별도 `현재 빌드` 영역에 아이콘 칩으로 표시하고 탭하면 정확한 효과를 툴팁으로 보여준다.
- 탭에 레드닷: 강화 가능/새 신물 획득 시
- 리스트 행은 UXML 템플릿 1개 + 데이터 바인딩으로 재사용한다(강화/스킬 공용). 소환사 탭은 별도 읽기 전용 텍스트 레이아웃을 사용한다.
- 탭 열면 하단 패널 확장 + 필드 축소, 단 전투는 계속 보이게

### 4.4 소환사 탭 프로필
- 별도 상시 노출 SummonerStrip은 사용하지 않는다. TopHUD의 소환사 프로필과 정보가 중복되고 탭 콘텐츠 높이를 소모하기 때문이다.
- 초상화 + 이름 + Lv + EXP 수치/바는 SummonerTab 상단 프로필 영역에 표시한다. 레벨업은 자동 처리하므로 SummonerTab과 UpgradeTab 어디에도 수동 레벨업 버튼을 표시하지 않는다.
- 프로필 아래 능력치와 영구/런 특성은 `UpgradeRow`를 재사용하지 않고 읽기 전용 일반 텍스트로 표시한다.

### 4.5 기타 키우기 문법
- 소환 이펙트: 일반 ★1 소환은 가볍게, ★2 직행 잭팟은 금색 강조. 머지 성공 시 성급 상승 이펙트
- 골드·계약서 등 필요한 재화가 부족하거나 슬라임 보유 한도가 가득 차면 버튼을 회색 처리하고, 수치는 항상 "현재→다음" 변화량 표기

레이어 3(개체 변수)은 v1과 동일: `{unit_concept}` = "goblin archer with short bow" 등.

- 배경은 크로마키 그린으로 뽑아 제거 (필드 통바닥 등 화면을 가득 채우는 배경만 예외)

### 5.2 도구 분담

## 7. 제출물 체크리스트 (5종, 하나라도 누락 시 탈락)

1. **플레이 빌드 + 소스** — WebGL을 GitHub Pages로, 소스 전체 동일 저장소, 커밋 기록 유지, public 권장 (비공개 시 심사 계정 dl_gameai_reviewer@nhn.com 초대). 유료 라이선스 없이 실행 가능해야 함
2. **플레이 영상** — YouTube 30~60초, 실제 플레이 화면만(AI 합성·조작 불가). 컷 구성안: 타이틀 3s → 배치+전투 20s → 예고 보고 재배치 15s → 합성/성장 10s → 보스 10s
3. **게임 소개 PDF** — 제목·한 줄 소개, 게임 방법(목표/조작/종료 조건), 실행 방법, 플레이 링크, 영상 링크
4. **AI 활용 기술 문서 PDF** — 3단 프롬프트 아키텍처 다이어그램, 카테고리별 템플릿·변수 표, 개선 사례 2~3개(before/after), 사용 기법 명명(few-shot, negative prompt 등), 코드·에셋·밸런싱·사운드 영역별 활용 내역, 외부 에셋·오픈소스 출처/라이선스 전부 명시
5. **팀원 롤 기술서** — 1인 참여 시 생략

## 8. 스코프에서 제외 (하지 말 것)
