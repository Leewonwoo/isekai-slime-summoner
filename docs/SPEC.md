# 십자 디펜스 (Cross Defense) — 프로젝트 스펙

> NAN 2026 (NHN Game × AI Hackathon) 사전 과제 제출작. **이 문서가 프로젝트의 단일 기준(Single Source of Truth)이다.**

## 0. 컨텍스트와 목표

- **대회**: NAN 2026, 사전 과제 심사로 10팀 선발 → 본선은 9/4~9/6 주제 현장 공개 48시간 해커톤 (NHN 사옥, 오프라인)
- **사전 과제 마감**: 2026-08-10 (접수 마감 후 수정 불가)
- **개발 기간**: 2026-07-11 ~ 08-10 (약 30일), 1인 개발
- **대회 슬로건**: "AI의 다음 단계를 설계할 디렉터" — AI를 어디에 쓸지 판단한 설계력이 심사 포인트

**이 프로젝트의 3중 목표:**
1. 10팀 안에 드는 사전 과제 (게임 완성도 + AI 활용 문서화)
2. 본선 48시간용 재사용 자산 축적 (Unity 보일러플레이트, 프롬프트 템플릿)
3. 커밋 기록 자체가 "한 달의 AI 활용 과정" 증거가 되도록 관리

## 1. 게임 컨셉

- **장르**: 자유 배치 소환 디펜스 × 로그라이크(메타 진행형) × 키우기
- **테마 (2026-07-15 개정)**: 중앙의 인간 **소환사**가 **슬라임 소환수**를 불러, 뷰포트 밖 여러 범위에서 몰려오는 **고블린 군단**을 막는다.
- **한 줄 요약**: 룰렛으로 슬라임을 소환하고 자유롭게 배치·3머지해, 움직이며 싸우는 소환수와 중앙 소환사의 원거리 공격으로 고블린 웨이브를 처치하는 디펜스
- **1런 길이**: 웨이브 수와 종료 시점은 고정하지 않고 `StageTimeline`의 목록과 이벤트로 결정한다.
- **핵심 딜레마**: 한정된 계약서로 어떤 소환수를 얻고 어디에 배치·재배치·머지할지, 5웨이브 기본 간격의 3택 특성 중 무엇을 고를지 판단한다.

## 2. 핵심 시스템

### 2.1 필드
- 4방향 레인과 고정 슬롯은 사용하지 않는다. 중앙에 **소환사(주인공)가 고정**되고 나머지 필드 전체를 자유 배치 공간으로 사용한다.
- **코어 = 소환사 본인 (2026-07-11 개정, 소환석 구조물 폐기)**: 지켜야 할 대상이 구조물이 아니라 소환사 자신. "코어 HP" = 소환사 HP (코드 식별자는 기존 core 유지 가능 — 일괄 리네임 금지)
- **런 흐름**: 런 시작 → 소환사 중앙 등장 → 룰렛 소환 → 버튼 자동 배치 또는 벤치 카드 드래그 배치 → 웨이브 전투
- **소환수 자유 이동**: 배치된 슬라임은 타겟을 탐색해 이동·공격하고, 필드 경계를 벗어나지 않으며 서로의 겹침을 완화한다. 플레이어는 필드 유닛을 드래그해 재배치할 수 있다.
- 적은 카메라 뷰포트 밖의 여러 외곽 범위에서 생성되어 중앙 소환사에게 이동하고, 도달 시 소환사 HP를 감소시킨다.
- 소환사는 중앙에서 움직이지 않지만 가장 가까운 적을 자동 원거리 공격한다. 필드를 클릭하면 해당 적 또는 클릭 방향으로 별도의 쿨다운 공격을 발사한다.
- 소환사 HP 0 = 런 종료(패배)

### 2.2 소환·머지 (핵심 경제 루프 — 2026-07-14 계약서 경제로 개정)
- **소환 = 운빨**: 런 전용 재화 **용병 계약서 1장** 소모 → 해금된 슬라임 풀에서 **종류 랜덤** 획득. 성급 없는 **기본 유닛**으로 등장
  - 골드는 몬스터 처치로 획득해 인게임 강화에만 사용하고, 소환 비용과 분리한다.
  - 계약서는 런 시작 시 **8~12장**을 지급하고, 일반 웨이브 클리어 시 **5~8장**, 5웨이브 단위 및 보스 클리어 시 **10~15장**을 지급한다. 정확한 수치는 웨이브 SO/밸런싱 CSV에서 조정한다.
  - 마지막 웨이브는 이후 소환 구간이 없으므로 계약서 대신 승리·보스 보상을 지급한다.
  - 낮은 확률(초기 ~5%)로 **★1 직행 잭팟** — 소환사 레벨/메타의 "소환 확률 개선" 스탯은 이 직행 확률을 올리는 것으로 재정의 (기존 등급 확률표 ★1 60/30/10은 폐기)
  - 연출: **슬롯머신 릴** (소환 탭 내). 3릴이 같은 유닛으로 정렬되면 ★1 직행 — 잭팟 확률을 슬롯 문법으로 시각화. 단 **로직 먼저, 릴 연출은 폴리싱 단계(3주차 이후)** — v1은 결과 즉시 표시 + 탭 스킵 가능해야 함 (소환을 수십 번 누르는 게임이므로 연출이 템포를 막으면 안 됨)
- **머지 (필드 드래그 3합성)**: 같은 종류 + 같은 성급 3개 = 성급 +1 유닛 1개. 필드 유닛을 같은 대상 위에 드롭하면 필드·벤치에서 세 번째 재료를 찾아 소비한다. **기본 → ★1 → ★2 → ★3 (최대)**
  - ★3 1개 = 기본 27개 환산 — 한 런에서 ★3은 1~2개 뜨는 감도를 목표로 소환 비용 커브를 밸런싱 CSV에서 조정
  - 벤치/필드 어디에 있든 같은 것 3개가 모이면 합성 가능하며, 드래그 중 Animated Sprite Outline으로 유효·무효·머지 대상을 구분한다.
- 벤치 12칸 (수치는 튜닝 가능), 벤치→필드 드래그 배치와 필드 자유 재배치
- 유닛 판매 가능 (소량의 골드 지급 — 벤치가 막힐 때의 배출구). 계약서는 환급하지 않아 판매→재소환 리롤 반복을 막는다.
- ⚠️ 해금 유닛이 늘수록 소환 풀 희석으로 머지 난도가 오름 — v1은 전체 풀 균등 랜덤으로 가고, 플레이테스트에서 희석이 체감될 때만 "런 시작 시 출전 덱 4~6종 선택"을 검토 (문제 확인 전에 미리 넣지 말 것)

### 2.3 유닛 — 슬라임 소환수 (8종)

| # | 유닛 | 공격 방식 | 속성 | 핵심 효과 |
|---|---|---|---|---|
| 1 | 주먹 슬라임 | 근접 단일 | 무 | 빠른 접근과 기본 근접 공격 |
| 2 | 물총 슬라임 | 원거리 투사체 | 무 | 빠른 공속의 범용 원거리 공격 |
| 3 | 불씨 슬라임 | 범위 공격 | 화염 | 밀집한 적 중심 스플래시 |
| 4 | 서리 슬라임 | 원거리 투사체 | 빙결 | 슬로우 부여 |
| 5 | 새싹 슬라임 | 원거리 투사체 | 자연 | 지속 피해 부여 |
| 6 | 공명 슬라임 | 지원 오라 | 무 | 반경 내 아군 공격속도 증가 |
| 7 | 팽창 슬라임 | 근거리 광역 | 화염 | 느리지만 강한 범위 폭발 |
| 8 | 빙정 슬라임 | 장거리 관통 | 빙결 | 여러 적 관통과 약한 슬로우 |

- 성급은 **기본 → ★1 → ★2 → ★3** 네 단계이며 ★3이 최대다.
- 성급 상승 시 공격력·공격속도·크기 모디파이어를 데이터로 갱신하고 AI의 타겟·공격 타이머를 초기화한다.
- 전용 성급 스프라이트가 준비되기 전에는 같은 기본 스프라이트와 속성 틴트·성급 표기를 사용한다.
- 모든 수치는 `SummonUnitData`로 교체 가능해야 하며 유닛별 런타임 코드를 복제하지 않는다.

### 2.4 성장 축 3개
1. **인게임 강화 (골드)**: 공격력/공속/소환사 HP 회복/치명타 — 키우기식 리스트에서 골드로 레벨업, 런 종료 시 리셋
2. **소환사 (주인공)**: 인게임 EXP로 레벨업 → 스탯 포인트/★1 직행(잭팟) 확률 개선. 스킬 개방과 아이템 장착의 주체
   - **기본 공격 프로토타입 (2026-07-14)**: 사거리 안의 가장 가까운 적을 자동 조준해 정적 스프라이트 투사체를 발사한다. 3종은 에너지 볼트(무속성·기본값) / 파이어볼(화염) / 아이스볼(빙결)이며 런타임 교체 가능하다. 투사체는 소환사 하위 `FirePosition`을 발사 원점으로 사용하고, 풀링한 뒤 진행 방향으로 회전한다. 첫 게임 3택 UI와 선택 저장 정책은 전투 기능과 분리해 후속 확정한다.
3. **메타 진행 (젬, 런 간 영구)**: 업그레이드 트리 15~20노드 — 시작 골드+, 시작 계약서+, 소환사 HP+, ★1 직행 확률+, 신규 유닛 해금. JSON + PlayerPrefs 저장

### 2.5 스킬 / 장비
- **스킬**: 웨이브 진행/소환사 레벨로 개방되는 액티브 스킬 (예: 메테오). 개방된 스킬은 필드 우하단 플로팅 버튼(쿨다운 표시)으로 노출
- **장비**: 웨이브 보상/보스 드랍 아이템을 유닛 또는 소환사에게 장착 (슬롯형 UI)

### 2.6 웨이브 설계 (규칙 기반 — 런타임 API 호출 없음)
- 웨이브 수는 고정하지 않고 `StageTimeline.waves.Count`로 결정한다. 각 웨이브는 적 조합·물량·HP/속도/보상 계수·스폰 간격을 가진다.
- Top/Right/Bottom/Left는 레인이 아니라 **뷰포트 밖 스폰 구역 가중치**다. 선택된 구역 안에서도 위치와 바깥 여백을 변주한다.
- 난이도 곡선(적 HP/수량)은 지수 성장 기반, 테이블 수치는 LLM으로 CSV 생성 후 SO로 임포트 — **개발 도구로서의 AI 활용 사례로 기술 문서에 기록**
- 런마다 약간의 변주를 주되 동일 시드에서는 같은 스폰 순서를 재현한다.
- 특성 3택 간격은 기본 5웨이브이며 타임라인에서 변경 가능하게 한다. 황금 고블린·행상인도 타임라인 이벤트 데이터로 등장 조건을 정한다.

### 2.7 적 — 고블린 군단

- 기본 고블린은 `MonsterData`의 HP·속도·접촉 피해·골드 보상·속성·크기 데이터로 구성한다.
- 고속·탱커·원거리형 등 기획된 몬스터는 같은 생명주기 위에 데이터와 행동 훅으로 확장한다.
- **황금 고블린**은 낮은 확률 또는 지정 웨이브 이벤트로 등장하고 일반 적과 구분되는 외형·보상·도주 규칙을 가진다.
- 적이 죽으면 PoolBoss 골드 오브가 처치 위치에서 TopHUD 골드 앵커로 흡수되고, 도착 시 재화와 숫자 카운트업을 확정한다.

### 2.8 속성 상성 (유닛 → 적 단방향)

- 속성 4종: **무(회색) / 화염(빨강) / 빙결(파랑) / 자연(초록)**
- 상성 고리: **화염 > 자연 > 빙결 > 화염**. 유닛의 공격 속성 → 적 속성으로만 적용 (적은 소환사만 공격하므로 역방향 상성 없음)
- 배율: 유리 **×1.5** / 불리 **×0.75** / 그 외 ×1.0. 무속성은 항상 ×1.0 (범용 안전픽 — 기본 해금 전사·궁수가 여기 해당)
- 웨이브 테이블(SO)에 방향별 적 속성 구성 필드 추가 → 런타임 스폰 규칙에 사용
- **설계 의도**: 상성은 재배치 딜레마의 정보축이다 — "동쪽에 화염 슬라임 예고 → 빙결 유닛을 동쪽으로 옮길까, 버틸까"가 매 웨이브의 판단이 되게 한다
- 배율 수치는 밸런싱 CSV/SO에서 조정 가능한 상수로 관리 (코드 하드코딩 금지)

## 3. 플랫폼·기술 스택

- **엔진**: Unity (2D, URP 불필요 시 Built-in)
- **빌드 타깃**: Android APK, IL2CPP + ARM64, 패키지 `com.wonucode.crossdefense`
- **화면**: 세로 1080×1920 고정(Portrait). 접수 요강의 기존 브라우저 플레이 요구와 APK 허용 여부는 제출 전 별도 확인한다.
- **UI**: UI Toolkit (UXML/USS) — HUD·하단 패널·배지 전담
  - PanelSettings: Reference Resolution 1080×1920, Scale With Screen Size, Match Width(0)
  - 유닛/몹/투사체/필드는 월드 오브젝트(SpriteRenderer) — UI Toolkit으로 필드를 그리지 말 것
  - 월드 앵커 UI(방향 배지 등)는 WorldToScreenPoint → 패널 좌표 변환으로 동기화
  - 드래그 앤 드롭(벤치 UI → 필드 월드): PointerDownEvent → 이동 임계값 → 월드 프리뷰 → PointerUpEvent에서 필드 경계와 겹침 검사 → 자유 좌표 배치 또는 벤치 복귀
- **연출**: 정적 스프라이트 + DOTween 코드 연출을 기본으로 하고, Animated Sprite Outline은 선택·배치 유효성·머지 대상 피드백에 사용한다.
- **아키텍처**: 웨이브/유닛/강화 데이터는 ScriptableObject, 몬스터·소환수·투사체·골드 드랍은 PoolBoss로 풀링한다.

```

 ├─ FieldOverlay.uxml    # absolute 레이어: 필드 상단 웨이브·잔여 몬스터, 스킬 플로팅 버튼
 │                       #   (월드 필드 상단에 고정)
 └─ BottomPanel.uxml
     ├─ TabBar (5탭 + 레드닷)
     └─ TabContent: SummonTab / UpgradeTab / SkillTab / GearTab / SummonerTab
         각각 별도 .uxml, 런타임 교체
         UpgradeTab·SkillTab·SummonerTab은 UpgradeRow.uxml 템플릿 공용
         (아이콘|이름+Lv|현재→다음|버튼) + 데이터 바인딩
         SummonerTab 상단에 초상화|Lv|EXP|강화 프로필 영역 배치
```

### 3.3 USS 규칙
- `variables.uss`에 전 색상/간격을 CSS 변수로 정의 (`--color-danger`, `--color-warning`, `--gap-sm` 등). **하드코딩 색상 금지**
- 컴포넌트별 uss 분리 (TopHUD.uss, BottomPanel.uss, UpgradeRow.uss)
- 위협도 색: danger(빨강)=위험 / warning(노랑)=보통 / muted(회색)=없음

### 3.4 코어 루프 착수 전 선행 작업 (이 순서대로)
1. WebGL 빌드 → GitHub Pages 배포 → 모바일 브라우저 실행 검증 (큐브 씬)
2. UI 스캐폴딩: 폴더 구조 + PanelSettings + RootLayout/TopHUD/BottomPanel 빈 껍데기 + variables.uss
3. **기술 스파이크 A**: 벤치(UI) → 필드(월드) 드래그 앤 드롭 브릿지 — 더미 슬롯 1개로 검증
4. **기술 스파이크 B**: TopHUD의 웨이브·잔여 몬스터 상태 표시가 세로 화면에서 읽히는지 검증
5. 여기까지 통과 후 코어 루프(스폰/이동/공격/웨이브) 착수

> 스파이크 A/B가 막히면 코어 루프보다 먼저 해결한다 — UI 아키텍처 전체가 여기 걸려 있음

## 4. UI/UX 스펙 (v2 확정 — 키우기 문법 차용)

> 설계 원칙: "문법은 키우기류 차용, 스킨은 오리지널. 하단 패널은 키우기 문법, 필드는 배치형 디펜스 문법."
> 키우기류와 달리 필드가 '조작하는 곳'이므로 필드 존 비중을 크게 유지한다.

### 4.1 존 레이아웃 (세로 3분할)

| 존 | 비중 | 내용 |
|---|---|---|
| 상단 HUD | ~8% | 소환사 아이콘·닉네임·레벨, 스테이지명, 골드·젬 캡슐 2종, 설정 |
| 중앙 필드 | ~50% | 십자 맵(7×7 그리드 개념), 필드 상단 웨이브·잔여 몬스터, 스킬 플로팅 버튼(우하단) |
| 하단 패널 | ~40% | 탭 5개 + 탭 콘텐츠. 소환사 정보·EXP·강화는 소환사 탭에 배치 |

### 4.2 웨이브 상태 표시
- 방향 예고 배지(N/E/S/W)는 사용하지 않는다.
- HUD 아래 필드 상단 중앙에 현재 웨이브("WAVE 12")와 해당 웨이브 잔여 몬스터 수를 함께 표시한다.
- 웨이브 방향 가중치와 실제 적 스폰은 런타임 게임 로직에서 처리하며, 상단 HUD는 표시 전용이다.

### 4.3 하단 탭 5개
- **소환**: 실제 보유 유닛만 들어가는 벤치 12슬롯(합성 가능 시 초록 테두리+"합성" 뱃지) + `보유 용병 n/12` + 용병 계약서 보유량 + `소환 ×1` 버튼(우측 엄지 위치) + ★1 직행 확률 노출. 전체 8종을 선택 슬롯처럼 상시 나열하지 않는다(선택 소환 오인 방지). 슬롯머신 릴 연출은 폴리싱 단계에 추가 (§2.2)
  - 합성 뱃지/프리뷰에 **다음 성급 진화 이름** 노출 (예: "기사 → 장군") — 진화 서사를 파는 지점 (§2.3)
- **강화**: 키우기식 리스트 행 [아이콘 | 스탯명+Lv | 현재→다음 수치 | 골드 버튼]. 골드 부족 시 버튼 회색 비활성. 길게 누르면 연속 강화
- **스킬**: 같은 리스트 행 구조, 버튼이 "개방"으로 변경
- **장비**: 슬롯형 (유닛/소환사 선택 → 장착 슬롯)
- **소환사**: 상단 프로필(초상화·Lv·EXP·강화) + 같은 리스트 행 구조(소환사 스탯) + 메타 트리 입구
- 탭에 레드닷: 강화 가능/새 장비 획득 시
- 리스트 행은 UXML 템플릿 1개 + 데이터 바인딩으로 재사용 (강화/스킬/소환사 3탭 공용)
- 탭 열면 하단 패널 확장 + 필드 축소, 단 전투는 계속 보이게

### 4.4 소환사 탭 프로필
- 별도 상시 노출 SummonerStrip은 사용하지 않는다. TopHUD의 소환사 프로필과 정보가 중복되고 탭 콘텐츠 높이를 소모하기 때문이다.
- 초상화 + Lv + EXP바 + 강화 버튼은 SummonerTab 상단 프로필 영역에서만 표시한다.

### 4.5 기타 키우기 문법
- 소환 이펙트: 일반 소환은 가볍게, ★1 직행 잭팟은 금색 강조. 머지 성공 시 성급 상승 이펙트
- 골드·계약서 등 필요한 재화가 부족하면 버튼을 회색 처리하고, 수치는 항상 "현재→다음" 변화량 표기

## 5. AI 에셋 파이프라인

### 5.1 3단 프롬프트 아키텍처 (기술 문서의 뼈대)

> **2026-07-11 v2 확정: 픽셀 아트로 전면 전환.** v1(SD 셀셰이딩)은 레퍼런스(픽셀 방치형 디펜스, 척박한 숲 개간지) 대비 톤 불일치로 폐기 — 사례: `prompt-cases/case-01-style-anchor/`. **아트 무드: 척박한 숲 한가운데 개간지에서 시작** (마른 풀·죽은 나무·바랜 흙, 채도 낮은 어스 톤).

```
[레이어 1: 스타일 앵커 — 전 에셋 공통 (v2 픽셀 아트)]
cute chibi pixel art game asset, 16-bit retro RPG style,
big head small body, 1px dark outline, muted earthy palette,
solid green background (#00FF00), centered
(레퍼런스 톤: 픽셀 방치형 디펜스 — 척박한 숲)

[레이어 2: 카테고리 변수]
고블린 캐릭터: + single front-facing goblin sprite,
                simple chunky silhouette, low information density,
                idle pose, weapon visible, no character sheet
적(슬라임):   + single {slime_concept}, symmetrical blob shape, front view,
              desaturated pale gray body (엔진 틴트용)
UI 아이콘:    + single flat pixel art game icon of {concept}, simple shape
배경/환경:    앵커의 캐릭터 구문(cute chibi, big head small body) 제거 후
              + top-down view, desolate forest atmosphere,
              no characters, no text, no UI
UI 프레임:    + rectangular frame/button designed for 9-slice scaling
              (uniform border thickness, identical corners), empty center
```

레이어 3(개체 변수)은 v1과 동일: `{unit_concept}` = "goblin archer with short bow" 등.

- 배경은 크로마키 그린으로 뽑아 제거 (필드 통바닥 등 화면을 가득 채우는 배경만 예외)
- **픽셀 아트 임포트 규격**: 생성물은 "가짜 픽셀"(픽셀 격자가 흐트러짐) → 최근접 보간(nearest-neighbor)으로 1/4~1/8 다운스케일해 격자 정리 후 사용. Unity 임포트는 Filter Mode **Point**, Compression **None**, Mipmap **Off**. 월드 캐릭터(소환사·아군·적)는 **PPU 200**, 배경·필드 타일은 **PPU 100**을 기본값으로 사용하며, 고블린은 소환사보다 작은 실루엣을 위해 **PPU 220**을 사용한다. 캐릭터는 소환사보다 크게 보이지 않도록 불투명 바운드도 함께 확인한다.
- **고블린은 정면 단일 스프라이트만 생성**: 이동 방향별 이미지는 만들지 않는다. 방향감은 이동 벡터·좌우 흔들림·스쿼시 연출로 표현하고, 생성본은 64px급 정보량·15색 이하로 단순화한 뒤 128×128px로 최근접 확대한다.
- 여러 유닛을 한 장에 그리드로 생성 후 잘라 쓰는 방식도 일관성에 유효

### 5.2 도구 분담
- 이미지: ChatGPT 이미지 생성 / 사운드 BGM: Suno / SFX: ElevenLabs 또는 jsfxr / 코드: Claude Code / 밸런스 테이블: LLM으로 CSV 생성

### 5.3 필요 에셋 목록 (생성 ~45장 이내)
- 고블린 캐릭터 8종 × 정면 단일 스프라이트 = **생성 8장** (방향별 슬라이스 없음, 등급 색변형은 틴트)

- UI 아이콘 ~20개 (**속성 아이콘 4종** — 무/화염/빙결/자연 — 포함)
- **UI 9-slice 프레임 2~3장** (돌 패널 프레임 / 나무 버튼 — 픽셀 프레임 UI용, ui-guidelines §4)
