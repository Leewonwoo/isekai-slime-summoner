# 전투 동적성 설계 — Position-Based Dynamics

> 기준 규칙은 `docs/SPEC.md` §2.1·2.6을 따른다. 이 문서는 PBD 구현·튜닝·검증 방법을 구체화한 하위 설계 문서다.

## 1. 목표와 적용 경계

PBD는 **Position-Based Dynamics**를 뜻한다. 이 프로젝트에서는 Rigidbody 힘 시뮬레이션 대신, 소환수와 고블린이 각자 AI 이동을 마친 뒤 서로 침투한 위치를 직접 보정하는 가벼운 접촉 제약으로 사용한다.

목표는 다음 세 가지다.

1. 한 타겟에 몰린 고블린이 한 점에 포개지지 않고 자연스럽게 둘러싼다.
2. 공격 사거리 안에서 멈춘 소환수도 서로 밀집을 풀어 역할별 실루엣이 읽힌다.
3. 큰 적과 높은 성급 소환수는 더 무겁게 버텨 전선의 형태가 계속 변한다.

PBD는 위치 표현만 바꾼다. 피해량, 공격 쿨다운, 속성 상성, 타겟 선택, 웨이브 난이도에는 보정값을 넣지 않는다. 따라서 물리 우연 때문에 승패나 동일 시드 스폰 규칙이 바뀌는 범위를 최소화한다.

## 2. 런타임 순서

```text
AI 타겟 갱신 → 원하는 방향으로 이동/공격 → PBD body 수집
→ 쌍별 침투 제약 1회 보정 → 개체별 보정 속도 제한
→ 소환수 필드 경계 보정 → Transform 반영
```

- 실행 위치: `SummonedUnitManager.LateUpdate`
- 대상: 살아 있고 활성화된 필드 소환수·고블린
- 제외: 드래그 중인 소환수, 쓰러졌거나 풀로 반환된 개체
- 복잡도: 현재 전투 규모에서는 단순한 `O(n²)` 쌍 검사를 사용한다. 실기기에서 동시 전투 개체가 64명을 지속적으로 넘고 PBD가 프레임의 1 ms 이상을 차지할 때만 공간 해시로 교체한다.
- 할당: 매 프레임 새 컬렉션을 만들지 않고 매니저가 보유한 리스트를 재사용한다.

## 3. 제약 규칙

두 body의 목표 거리는 기본적으로 `(반지름 A + 반지름 B) × 팀별 간격 배율`이다.

- 소환수↔소환수: 외형 반지름 합의 `0.82`
- 고블린↔고블린: 외형 반지름 합의 `0.78`
- 소환수↔고블린: 외형 반지름 합의 `0.52`
- 적대 body 간 목표 거리는 두 개체의 근접 접촉 가능 거리 중 작은 값의 `95%`를 넘지 않는다. 큰 몬스터가 PBD 때문에 자기 공격 사거리 밖으로 밀려나는 문제를 막는다.
- 보정량은 inverse mass 비율로 나눈다. 기본값은 소환수 `0.65`, 고블린 `1.0`이며, 외형 스케일이 클수록 inverse mass를 낮춰 더 무겁게 만든다.
- 목표 거리보다 겹친 양이 `0.06` 월드 유닛 이하이면 그대로 두어 얕은 접촉에서 계속 벌어지는 현상을 막는다.
- 한 개체의 PBD 이동은 초당 `0.90` 월드 유닛을 넘지 않는다. 프레임 `deltaTime`을 곱해 프레임률이 달라도 같은 속도로 천천히 침투를 푼다.
- 두 중심이 완전히 같은 경우 인덱스 기반 고정 방향을 사용한다. NaN과 프레임별 랜덤 흔들림을 만들지 않는다.

모든 값은 씬의 `GameManager > Combat Motion` 직렬화 설정으로 조정한다. `GameManager`가 런타임에 생성하는 `SummonedUnitManager`에 같은 설정 인스턴스를 전달한다.

| 설정 | 기본값 | 체감 |
|---|---:|---|
| Solver Iterations | 1 | 현재는 반발감을 줄이기 위해 한 번만 보정 |
| Correction Strength | 0.38 | 겹침을 즉시 튕겨내지 않고 천천히 해소 |
| Summoned Unit Spacing Scale | 0.82 | 아군 진형에 약간의 시각적 겹침 허용 |
| Monster Spacing Scale | 0.78 | 고블린 군중의 밀도 유지 |
| Opposing Spacing Scale | 0.52 | 양 진영이 접촉한 전선의 밀착감 |
| Penetration Slop | 0.06 | 이 값 이하의 얕은 겹침은 보정하지 않음 |
| Max Correction Speed | 0.90 | PBD가 개체를 밀 수 있는 초당 최대 거리 |
| Summoned Unit Inverse Mass | 0.65 | 낮을수록 소환수가 전선을 잘 지킴 |
| Monster Inverse Mass | 1.00 | 높을수록 고블린이 옆으로 잘 흘러감 |

## 4. 전투 동적성 축

PBD만으로 전투 재미를 만들지는 않는다. 기존 스펙의 네 가지 입력축이 서로 다른 시간 규모로 전선을 바꾸게 한다.

| 시간 규모 | 변화 원인 | 플레이어가 읽는 것 | 대응 |
|---|---|---|---|
| 매 프레임 | PBD 밀집 해소, 자유 이동 | 고블린이 전선 옆으로 흐르는 공간 변화 | 유닛 재배치 |
| 수 초 | 타겟 사망·재탐색, 사거리·역할 차이 | 탱커가 버티고 원거리·범위 유닛이 화력을 투사 | 클릭 집중 공격 |
| 웨이브 내부 | 스폰 구역·간격·물량 | 어느 외곽에서 압력이 커지는지 | 전선 분산 또는 집중 |
| 웨이브 사이 | 계약서 소환·3머지·강화·속성 구성 | 다음 압력에 맞는 성장 선택 | 소환·머지·강화 |

추가 AI 디렉터나 런타임 LLM 없이 `StageTimeline`, 유닛 역할, 재배치만으로 이 변화를 만든다.

## 5. 웨이브 리듬 설계

20웨이브 기준으로 사용할 수 있는 리듬 원칙이며, 실제 웨이브 수는 `StageTimeline`을 따른다.

- 도입: 한 스폰 구역·낮은 밀도로 PBD 흐름과 재배치를 학습한다.
- 압박: 서로 다른 두 구역을 짧은 간격으로 교차시켜 전선이 한쪽에 고정되지 않게 한다.
- 해소: 물량 또는 HP를 직전 압박보다 낮추고 계약서 사용·머지 판단 시간을 준다.
- 시험: 속성 또는 적 크기 한 축만 크게 바꿔 플레이어가 실패 원인을 읽게 한다.
- 보스: 잡몹의 밀집 압력과 큰 inverse mass 개체의 전선 고정을 함께 보여주되, 새 물리 규칙은 추가하지 않는다.

### 전투 후 복귀 포메이션

웨이브가 끝나면 전장에 흩어진 소환수가 소환사 주변으로 복귀해 다음 전투를 기다린다.

- 적용 상태: `Prepare`, `Intermission`, `TraitChoice`, `Merchant`, `Victory`
- 배치: 반경 1.15부터 0.7 간격의 동심원, 링당 기본 6명
- 역할 순서: 지원 → 원거리/관통 → 범위 → 근접. 안쪽에는 지원·원거리, 바깥쪽에는 근접 전선을 둔다.
- 안정성: 같은 역할은 `InstanceId` 순서를 사용해 웨이브마다 자리가 무작위로 뒤집히지 않는다.
- 이동: 기본 초당 3.4 월드 유닛으로 복귀하며 이동 프레임이 있는 유닛은 기존 이동 애니메이션을 재사용한다.
- 플레이어 우선: 비전투 중 벤치 또는 필드 드래그가 시작되면 해당 복귀를 취소한다. 플레이어가 잡아 둔 위치를 다음 웨이브 직전에 다시 덮어쓰지 않는다.
- PBD: 복귀 중에만 비전투 PBD를 유지하고 모든 유닛이 슬롯에 도착하면 계산을 중단한다.

값은 `GameManager > Combat Motion > Summon Formation`에서 조정한다.

## 6. 검증 기준

자동 검증:

- 같은 팀 침투가 설정 간격까지 해소되는가
- inverse mass가 작은 개체가 덜 움직이는가
- 적대 간격이 근접 공격 가능 거리보다 커지지 않는가
- 동일 위치 두 개체가 유한한 고정 결과를 만드는가
- 허용 오차 안의 얕은 겹침이 추가 이동을 만들지 않는가
- 깊은 겹침도 개체별 보정 상한을 넘지 않는가

PlayMode/Android 검증:

- 12 소환수 + 40 고블린에서 한 점 포개짐이 지속되지 않는가
- 큰 고블린도 멈춘 뒤 실제로 공격하는가
- 드래그 중인 소환수가 손가락 위치에서 PBD로 밀리지 않는가
- 필드 경계에서 소환수 군집이 눈에 띄게 떨리지 않는가
- PBD 구간 CPU가 실기기 프레임당 1 ms 이하인가
- 웨이브 종료 후 소환수가 역할 순서대로 소환사 주변에 복귀하는가
- 준비 구간에서 유닛을 드래그한 뒤 자동 포메이션이 수동 위치를 덮어쓰지 않는가

튜닝은 `Iterations → 팀별 Spacing → Penetration Slop → Max Correction Speed → Inverse Mass → Strength` 순서로 한다. 피해량이나 이동속도로 공간 문제를 덮지 않는다.
